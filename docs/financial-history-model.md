# 财务历史与持仓模型

适用版本：`1.1.1`。

## 业务口径

卡片档案、交易事实、费用事实和估值事实分别保存。交易金额表示整笔交易总额；估值金额表示单张卡片在该日期的估值。CNY 与 USD 始终独立核算，不做隐式汇率换算。

本版本只支持正常买入与正常出售，不提供退款、退货、交易取消或冲销流程。

## 交易与数量

`CardTransaction.kind` 只允许：

- `purchase`：增加持仓数量和库存成本。
- `sale`：减少持仓数量，出售数量不得超过该币种当前持仓。

每笔交易保存总金额、币种、正整数数量、发生日期、来源、备注和数据来源标记。`Card.holdingQuantity` 是由交易历史维护的当前数量快照；没有交易历史的既有持有卡默认按 1 张处理，已售和目标卡按 0 张处理。

录入工作台允许填写初始数量。多张初始持仓必须填写购买日期；即使购买成本未知，也会建立金额为 0 的期初购买事实，保证之后能够正确部分出售。持仓归零时收藏状态自动变为“已售出”，已售档案重新买入后自动恢复为“持有中”。

## 费用归属

费用类型用于描述费用性质，例如评级、运费、税费、保险、存储、平台费用或其他；界面中的“费用归属”由 `CardExpense.context` 保存，用来明确费用进入哪条核算路径：

- `purchase`（买入相关）：计入库存成本。
- `grading`（评级相关）：计入库存成本。
- `sale`（出售相关）：从出售收入中扣除。

界面分别使用“计入买入成本、计入评级成本、从出售收入扣除”，避免把费用类型与计算去向混淆。汇总中的“计入持仓成本的费用”是买入成本费用与评级成本费用之和，不是需要额外录入的费用类型。

新录入的出售相关费用必须绑定同一卡片、同币种的一笔具体出售记录。既有平台费用在升级时保留为未绑定的历史出售费用，编辑时可以补充关联。

v1.1.0 数据升级时会一次性回填：运费发生日期与卡片购入日期（或购买交易日期）为同一日的，记为买入相关；其他运费记为评级相关。既有评级等非出售费用默认记为评级相关，平台费用记为出售相关。完成升级后不会重复回填；恢复 v1.1.0 备份时，会对该备份重新执行一次升级和回填。

## 移动平均成本

每个币种独立按业务日期排序计算：

1. 买入总额与当时已发生的买入/评级相关费用加入剩余成本。
2. 移动平均单位成本 = 出售前剩余成本 ÷ 出售前剩余数量。
3. 部分出售按该单位成本结转已实现成本；最后一张出售吸收最小货币单位的分摊尾差。
4. 已实现盈亏 = 出售总额 - 出售相关费用 - 已结转成本。
5. 未实现盈亏 = 最新单张估值 × 剩余数量 - 剩余成本。
6. 总盈亏 = 已实现盈亏 + 未实现盈亏。

同一日期内按“买入 → 计入持仓成本的费用 → 出售”的顺序计算。若持仓已经全部售出后才补录买入或评级相关费用，该费用直接增加已实现成本，避免形成没有数量支撑的剩余成本。

财务趋势图复用上述排序和移动平均计算结果。持仓成本使用阶梯线；持仓估值只在已录入的估值日期显示快照点，不补造缺失日期的市场价格。累计成本构成展示历史买入金额、买入成本费用和评级成本费用，因此不等同于部分出售后的当前剩余成本。

## 数据安全

- 金额按最小货币单位整数保存，不以浮点数保存历史事实。
- CNY/USD 不混算，估值不覆盖交易和费用事实。
- v1.1.0 升级到 v1.1.1 前，在数据库相邻的 `schema-backups` 目录创建 SQLite 一致性快照。
- 升级、费用回填和交易表约束替换在事务中完成；失败时保留原数据库。
- 财务记录新增、编辑或删除与持仓汇总重算在同一事务中完成，超卖会使整笔操作回滚。
- 从旧备份恢复时先在暂存区升级和校验，成功后才替换当前数据；应用无需退出重启。
