# 应用主题

产品版本：`1.3.5`。

设置 → 主题提供“经典、极简展厅、午夜典藏、暖纸档案”。主题区只展示预览图与名称，用户选择后立即生效并保留；各主题平等呈现，不设置默认标记或恢复入口。经典主题的各页面统一使用首页背景图。字体、文字排版和业务功能保持原样。

主题覆盖首页、展示、卡片档案与财务、组合分析、分享编辑、计划和设置。经典主题各页面使用同一背景效果；其他主题在首页与展示使用完整背景，数据和编辑页面弱化背景，优先保证内容可读。分享集的主题、背景、预览和静态导出独立于应用主题。

## 保存与首屏

- `card_vault_app_theme` 保存为一年有效期的本地 Cookie，仅包含主题 ID，不写入收藏数据库。浏览器或桌面配置被清除后回到经典。
- 根布局在服务端读取 Cookie，将已校验的主题标识和颜色变量直接输出到 HTML，避免等待客户端加载后才改变颜色。
- 未知、失效或异常主题值回退到经典。主题 ID 必须来自固定注册表，不允许从 Cookie 注入颜色、CSS 或外部背景地址。
- 背景以本地 WebP 随应用发布，不需要联网。新增三张背景由 imagegen 生成，原始尺寸 1672 × 941，压缩后合计约 326 KiB；资源位于 `public/app-themes/`。

## 添加主题

1. 在 `public/app-themes/` 添加经过压缩的本地背景。
2. 在 `lib/app-themes.ts` 的 `appThemes` 注册表增加唯一 ID、中英文名称、背景路径及完整颜色配置。设置卡片与允许的主题 ID 随注册表自动扩展。
3. 新的组件沿用 `--ink`、`--surface`、`--surface-soft`、`--accent`、`--muted-ink` 等公共变量。迁移已有组件时使用 `--theme-*` 变量并保留原色值作为 fallback，避免影响经典主题。预览缩略图若需专属颜色，可在 `app/themes.css` 添加对应样式。
4. 不修改 `lib/share-themes.ts` 或导出渲染样式，它们属于分享集主题系统。
5. 运行主题单元测试和 `tests/ui/themes.spec.mjs`，检查颜色对比、键盘选择、重载与无 JavaScript 首屏、手动切换、各主要页面及分享预览独立性；检查截图后再更新基线。

## 验证范围

自动检查正文、辅助文字、链接、按钮及财务正负状态的主要颜色组合达到 4.5:1 对比度。真实页面仍需检查半透明面板、图片边缘、图表与交互状态，不能仅凭颜色变量测试判定全部视觉合格。
