# Card Vault v1.0.19 更新说明

发布日期：2026-08-21。

## 限量编号卡正确性

- 录入和编辑页面新增“限量编号卡”明确开关。
- 即使没有手动勾选，只要“编号”或“编号范围”填写了有效内容，服务端仍会自动保存为限量编号卡。
- 新增 `009_backfill_serial_numbered_v1_0_19` 数据迁移，一次性回填已有编号信息完整但状态错误的卡片。
- 迁移继续沿用升级前 SQLite 快照、事务执行、完整性检查和旧备份暂存迁移机制。
- 卡片 HTTP 端到端测试会验证 `/99` 等编号信息最终写入 `isSerialNumbered`。

## 数据校验与排序语义

- 服务端统一限制公开状态和收藏状态，不再接受列表之外的值。
- 球员、卡名、运动、卡片属性、评级链接、描述、备注和标签增加明确长度或数量限制。
- 无效购买日期和估值日期不再静默转换为空值，而是向用户返回可处理的校验错误。
- 标签写入时去除空项和重复项，单卡最多 30 个标签，单个标签最多 40 个字符。
- 首页“价格升序/降序”改为“CNY 总投入升序/降序”，并按财务历史生成的 CNY 兼容总投入快照排序。
- 首页高级筛选移除“编号”和“编号范围”输入框，改为“限量卡：是/否”；通用关键词搜索仍可匹配编号内容。
- 排序增加“CNY 估值升序/降序”，按财务历史生成的 CNY 最新估值快照排序。

## 本地服务与 Electron 安全

- 桌面应用每次启动生成独立随机会话令牌，并在加载页面前写入 HttpOnly、SameSite=Strict Cookie。
- 本地 Next.js 服务在桌面模式下校验精确的 `127.0.0.1` Origin、会话令牌和跨站写请求来源；直接开发和自动化 E2E 模式保持兼容。
- 健康检查使用独立会话请求头，不需要公开关闭本地服务保护。
- 页面响应增加 CSP、`Referrer-Policy: no-referrer`、`X-Content-Type-Options: nosniff` 和禁止框架嵌入设置。
- Electron 渲染进程启用 sandbox，继续保持 context isolation、禁用 Node.js 集成和不安全混合内容。
- AI 设置、存储迁移、备份、恢复、健康检查和孤儿文件操作增加 IPC sender Origin 校验。

## 质量门槛

- 新增 ESLint flat config，检查 JavaScript、TypeScript、React Hooks 和 JSX 无障碍规则。
- 自动化测试增加行、函数和分支覆盖率门槛；v1.0.19 发版候选基线为 117 项测试全部通过，整体行覆盖率约 90%。
- GitHub Windows Quality 工作流在完整发布检查前执行生产依赖安全审计。
- React 与 React DOM 固定升级到 19.2.8，避开 React Server Functions 拒绝服务公告影响的 19.2.0–19.2.7 版本范围。
- 完整发布检查继续覆盖编码、版本元数据、类型、生产构建、卡片 HTTP E2E 和分享 HTTP E2E。

## 数据兼容

- v1.0.19 不改变财务历史或分享展馆表结构。
- 旧数据和旧备份会在应用启动或恢复暂存阶段自动完成限量编号回填。
- 安装新版不会主动删除收藏数据；升级前仍建议在设置页执行一次完整备份。
