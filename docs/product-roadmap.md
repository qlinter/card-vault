# Card Vault 产品开发路线图

最后确认：2026-08-13。

本文档记录 v1.0.16 之后的长期产品方向，供需求取舍、版本规划和发布验收参考。路线图不是不可变的承诺；如果真实使用反馈、数据安全风险或平台条件发生变化，可以调整单个版本范围，但应保留本文确定的产品原则和阶段顺序。

## 产品定位

Card Vault 将继续以“本地优先的个人球星卡收藏管理工具”为核心，逐步从收藏档案工具发展为个人收藏资产管理与展示平台。

后续建设围绕四条主线展开：

1. 更快录入和维护收藏数据。
2. 建立可解释、可追溯的持仓与收益体系。
3. 提供由确定性数据支撑的组合分析和收藏决策辅助。
4. 提升分享展馆的成品质量，并在资源成熟后提供可选的在线发布与同步。

## 开发原则

- 优先改善高频操作，再扩展低频高级能力。
- 本地功能不依赖在线账户或持续联网。
- 用户数据、图片和财务历史默认保存在本机。
- 程序负责金额、比例、收益和趋势等确定性计算；AI 负责识别、解释、归纳和建议。
- CNY 与 USD 默认独立核算，不使用未经用户确认的隐式汇率。
- 高风险数据迁移与大型界面改版不放在同一个版本中。
- Cloudflare Drop 继续作为人工临时发布渠道，直到具备长期服务器或正式 Cloudflare 项目资源。
- 功能增长不得削弱 v1.0.16 建立的备份、恢复、测试和可重复发布基线。

## v1.1.0：卡片录入工作台 2.0

### 目标

优先改善最常用的录入和维护流程，让同套卡、同球员、拆盒或批量图片场景能够连续处理，并减少重复劳动和误录。

### 核心范围

- 连续录入模式：保存后可继续录入、查看详情或复制新增。
- 批量图片导入，建立待处理队列。
- AI 批量识别，但每张卡必须由用户确认后才能写入正式数据。
- 复制上一张卡片的年份、品牌、产品线、球队等公共字段。
- 常用录入模板，例如同一套卡、同一球员或同一次拆盒。
- 根据球员、年份、产品线、卡号、平行版本和编号提示疑似重复卡。
- 录入草稿箱和中断恢复。
- 图片自动旋转、压缩、正反面排序和失败重试。
- 键盘快捷操作、必填项定位和更清晰的保存反馈。
- AI 识别结果显示置信度和待确认字段。

### 暂不包含

- 不在本版本引入部分出售和复杂收益计算。
- 不让 AI 在用户确认前直接批量写入正式收藏。
- 不引入服务器账户或云端队列。

### 完成标准

- 连续录入和草稿恢复均有自动化测试。
- 批量任务中单张失败不会丢失其他任务。
- 重复提示只提供判断依据，不自动覆盖已有卡片。
- 旧版单卡录入流程和现有数据保持兼容。

## v1.2.0：持仓与收益模型

### 目标

让交易历史能够准确表达分批买入、持仓数量、部分出售、剩余成本以及已实现和未实现收益。

### 核心范围

- 分离卡片档案、持仓数量与交易事实。
- 支持同一资产分批买入和部分出售。
- 支持退款、退货、交易取消和冲销记录。
- 费用可关联买入、出售、评级或持有过程。
- 自动计算当前数量、剩余成本、已实现收益、未实现收益和总回报。
- 初期只支持一种明确的成本分配方式，优先考虑移动平均法。
- CNY/USD 分币种计算。
- 需要统一基准币种时，由用户录入或确认汇率及日期，并保留汇率快照。
- 财务纠错优先采用追加纠正或冲销，减少直接删除历史事实。

### 风险边界

- 这是独立的高风险数据库版本，不与大型界面重构合并。
- 迁移前必须生成数据库快照，迁移失败不得替换当前数据。
- 必须覆盖分批买入、部分出售、退款、跨币种隔离和旧备份恢复测试。

## v1.3.0：收藏组合中心

### 目标

将首页摘要和组合分析扩展为独立的收藏组合页面，为日常整理、估值维护和结构判断提供可靠视图。

### 核心范围

- 总估值、成本、已实现收益和未实现收益趋势。
- 按球员、运动、球队、年份、品牌、评级机构和卡片类型分析。
- 数量集中度与估值集中度。
- 最近 30/90/180 天估值变化。
- 估值来源构成、估值时效和过期提醒。
- 未估值、无图片、缺少交易和资料不完整清单。
- 高价值持仓、高成本持仓和已售卡片复盘。
- 将筛选条件保存为收藏视图，例如核心收藏、待评级、在售或待更新估值。
- 支持两个时间点或两个收藏视图之间比较。
- 保存组合分析快照并比较结构变化。

### AI 边界

- 所有金额、比例、收益和趋势先由程序计算。
- AI 只能解释程序生成的统计快照，不能自行推算汇率或市场价格。
- AI 结论显示证据、数据充分度和适用范围。

## v1.4.0：分享展馆 3.0

### 目标

把开发重点从继续堆叠编辑选项转向展馆成品质量、移动端体验和大型分享集性能。

### 核心范围

- 展馆模板库和模板预览。
- 桌面、平板和手机响应式预览。
- 自动优化图片尺寸、WebP 质量和加载顺序。
- 支持分享首页、章节页和球员专题页。
- 支持卡片故事、收藏背景和重点卡说明。
- 字体层级、间距、封面安全区和可访问性检查。
- 分享二维码。
- 导出差异摘要，说明相对上次导出发生的变化。
- 大型分享集使用图片懒加载、分页或分段加载。
- 建立桌面和手机截图基线，防止视觉回归。

### 发布边界

- 继续支持人工上传到 Cloudflare Drop。
- 不记录一小时临时 URL 或认领链接。
- 永久发布、更新和撤回留到具备长期资源后实现。

## v1.5.0：批量数据与迁移中心

### 目标

让大规模收藏能够安全导入、批量维护、导出和迁移到新电脑。

### 核心范围

- CSV/XLSX 导入向导、字段映射和写入前预览。
- 重复项检测以及跳过、覆盖、合并策略。
- 批量修改状态、标签、可见性、球队、系列和估值。
- 公开字段导出和完整收藏数据包导出。
- 完整数据包不得包含 AI Key 或本机私密配置。
- 换机迁移向导检查数据库和媒体完整性，并在恢复后比对数量。
- 备份说明、备注和迁移报告。
- 批量操作支持失败清单和可恢复重试。

## v1.6.0：提醒与收藏计划

### 目标

让 Card Vault 从被动记录工具发展为主动协助整理收藏的本地管理工具。

### 核心范围

- 估值长期未更新提醒。
- 评级送出时间和预计处理周期提醒。
- 在售时间过长提醒。
- 目标卡愿望清单、预算和购买计划。
- 待补图片、待补资料和待处理草稿。
- 本地通知中心。
- 每周或每月收藏摘要。
- 提醒数据默认保存在本机，不依赖服务器。

## v2.0.0：可选在线服务

### 启动条件

只有在长期服务器、正式 Cloudflare 项目、身份认证方案和运维能力明确后才启动。

### 候选范围

- 用户账户和设备授权。
- 加密的数据同步。
- 冲突检测、操作版本和历史恢复。
- 媒体对象存储。
- 永久分享链接。
- 发布、更新、撤回和访问权限。
- 在线分享版本记录和可选访问统计。

### 明确限制

- 不直接使用云盘同步正在使用的 SQLite 文件。
- 多设备同步必须建立在记录版本、操作日志或服务端事务之上。
- 在线能力应保持可选，本地收藏管理不能因服务器不可用而停止工作。

## 跨版本体验标准

每个功能版本都应尽量满足以下体验要求：

- 长表单和复杂编辑自动保存草稿。
- 危险操作提供二次确认、撤销或安全备份。
- 长时间任务显示阶段、进度、成功结果和失败恢复方法。
- 错误信息同时说明发生了什么以及用户可以怎样处理。
- 空状态提供明确的下一步入口。
- 保存成功后允许继续当前工作流，不强制跳转。
- 重要页面支持合理的键盘操作。
- 校验失败后保留用户已填写内容。
- 批量任务支持局部失败，不因单项错误丢失全部进度。
- 新功能必须纳入备份、恢复、旧数据迁移和隐私边界评估。

## 跨版本工程验收标准

每个正式版本发布前至少完成：

- 使用锁文件在干净环境安装依赖。
- UTF-8、版本元数据和 TypeScript 检查。
- 与新增功能对应的业务规则测试。
- 卡片与分享关键 HTTP 端到端测试。
- 生产构建和打包后运行时冒烟测试。
- 安装包、便携 ZIP、内部版本和 SHA-256 校验。
- 数据库变更必须提供迁移前快照、失败回滚和旧备份恢复测试。
- 生产依赖安全审计。
- 更新 README、对应版本说明和本路线图实施状态。

## 规划维护方式

- 开始一个版本前，将其核心范围拆成可验证的开发批次。
- 新需求优先归入最匹配的既定版本，避免无边界插入当前版本。
- 如需调整顺序，应记录调整原因、依赖条件和数据风险。
- 版本完成后在本文件中标记实际交付结果，并将未完成项重新归档。
- 小型修复和稳定性收口可以使用补丁版本，但不应借补丁版本引入高风险数据模型。
