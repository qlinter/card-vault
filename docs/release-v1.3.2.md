# Card Vault v1.3.2

源码与分发日期：2026-09-09。状态：源码审核、清理与验证完成，**经用户确认已生成 Windows x64 未签名安装包与便携包，并通过产物验收**，尚未上传发布。本版是 v1.3.1 的安全、可靠性与大收藏性能更新；旧分发文件不会自动获得这些修复。

## 范围与改进

1. **依赖安全**：Next.js 16.3.0 → 16.3.3、sharp 0.35.3 → 0.35.4、js-yaml 4.3.1 → 4.3.2，同步相关平台组件和锁文件。修复依据：[Next.js](https://github.com/advisories/GHSA-p293-qw3h-jr36)、[sharp](https://github.com/advisories/GHSA-rgj7-g3m4-5g8c)、[js-yaml](https://github.com/advisories/GHSA-2883-xcg3-v3hh)。保留完整审计范围及 high 失败门槛。
2. **启动诊断**：子进程输出流关闭后再报告失败，保留底层中文错误和真实日志路径。准备流程先验证数据库再清理旧构建，并复用 prebuild 的 Prisma 生成步骤，避免重复生成。仅同步 Git 不会更新个人数据库；9 月 9 日本机缺失辅助结构曾在备份、副本验证后单独修复，该操作不加入产品自动升级能力。
3. **配置保存**：存储路径和加密 AI 配置共用完整替换写入函数，临时文件写完并刷新后再替换原文件。写入或替换失败时保留旧配置，不会先截断旧文件。AI 密钥加密方式及配置格式不变。
4. **恢复校验**：来源备份校验后，复制出的暂存目录再次校验文件数量、大小、SHA-256 和数据库记录数，全部通过才切换。复制损坏或来源在复制期间变化时保留原数据。
5. **路径边界**：Windows 下同一路径的大小写变化按同一路径处理；名为 `..photos` 等真实子目录不能绕过数据/备份目录包含检查。
6. **计划查询**：每 250 张卡片即时生成提醒，释放该批原始历史；购买缺失仅查询是否存在未知成本记录。摘要改由数据库计数，兼容文本/整数日期并排除未来事件；最近有效估值使用单次扫描，保持 180 天规则、提醒指纹及排序。
7. **密集组合历史**：历史记录只排序一次，按月推进交易、费用和各币种最新报价；业务事实不变时复用余额，报价更新不再触发整段历史核算。仍调用共享核算函数，保留月末截点、舍入、未知成本、缺失汇率、覆盖率及同日估值规则，不增加跨请求缓存。
8. **大规模导出**：先取得一致 SQLite 快照，按卡片 ID 和记录 ID 分批读取，每批最多 250 条。CSV 按行写入，XLSX 使用逐表 XML 和 ZIP 流，完成后以 64 KiB 分块下载，避免整本工作簿及整文件缓冲。最多同时两个导出，生成限时 10 分钟；正常完成、取消和异常清理临时文件。超出 XLSX 单表行数后自动分表。字段、公开过滤、选中范围、CSV 文本转义和财务口径保持一致。
9. **分享与验证维护**：同一主体分组改用追加，避免反复复制数组。新增冻结旧算法对照、XLSX 格式/故障测试和真实 HTTP 导出测试，并纳入发布门槛；新增可重复运行的历史函数及大规模导出基准。

产品版本为 `1.3.2`，数据库结构标记仍为 `1.3.0`，核算版本仍为 `physical-position-v2`。完整当前格式的 v1.3.1 数据可继续使用，不新增迁移或改写用户业务数据。页面布局、字重和入口保持现有方案。

## 密集历史与导出性能

2026-09-09，Windows / Node 24.14.0，生产构建和隔离合成数据。以下不同基准分别运行；函数对照为预热后五轮交替测量的中位数，HTTP 指标为单次测量，不代表其它设备或真实数据的性能承诺。

- **历史计算函数对照**：500 张卡片，每卡 240 条估值；旧实现 996.7 ms，新实现 150.4 ms，约减少 85% 耗时。全部月份的金额、缺失标记和覆盖率相同；另用双币付款、乱序/同日/未来估值、未知成本、缺失汇率场景做回归。该比例仅用于函数，不能解释为整页提速。
- **完整组合页**：每卡 2 笔交易、12 笔费用、24 条月度估值及 2 张 1600×2400 合成 WebP（约 19 KB/张）。1000 / 5000 / 10000 张卡片分别为 871 / 3612 / 6973 ms；万卡场景整个基准过程的服务进程采样峰值约 557 MB。数据库读取、报表投影和页面输出仍影响整页耗时，不是固定内存实现。

导出基准每卡 38 条估值，并带约 2.6 KB 文本字段；XLSX 校验 Cards 与 Financial history 的全部行数，CSV 仅含档案。文件生成完成才返回响应，下载在随后完成；表中总耗时包含下载，不含测试端的 XLSX 解析时间。

| 卡片数 / 财务记录数 | 格式 | 开始下载前 | 下载完成 | 文件大小 | 服务进程采样峰值 RSS |
| --- | --- | --- | --- | --- | --- |
| 1000 / 38000 | CSV | 239 ms | 253 ms | 2,686,728 B | 141 MB |
| 1000 / 38000 | XLSX | 2238 ms | 2247 ms | 2,681,141 B | 315 MB |
| 10000 / 380000 | CSV | 1115 ms | 1220 ms | 26,874,228 B | 248 MB |
| 10000 / 380000 | XLSX | 18111 ms | 18207 ms | 26,789,024 B | 316 MB |

RSS 按 100 ms 采样，包含整个服务和原生库，不是导出净增量，也可能漏过短峰值。四次导出依次在同一进程进行，基线分别为 97/157/108/243 MB；运行时回收和缓存会影响数值。分批行对象及下载队列有上限，单个超长字段、SQLite 页面缓存和压缩库仍影响内存。临时磁盘须容纳数据库快照、未压缩工作表与最终文件；强制结束进程可能留下系统临时目录文件。

XLSX 使用明确文本/数值/布尔类型、冻结表头和自动分表，已用 ExcelJS 普通及流式读取验证；尚未做真实 Excel 应用打开验收。公开 XLSX 仅含公开档案，不含私人备注与财务页。单表最多 1,048,576 行（含表头），分表逻辑使用缩小行数门槛测试；本轮没有生成百万行文件。导入的 10 MB/10000 行/首表限制不变。
