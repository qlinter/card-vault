# Card Vault

Card Vault 是一个本地优先的球星卡管理工具，用于录入、筛选、展示和桌面端运行个人收藏数据。

项目使用 `Next.js + React + Prisma + SQLite + Electron` 搭建。卡片数据和图片默认保存在本地，适合离线使用，也支持在桌面端切换数据存储路径。

## 版本说明

### 1.0.0 基础版本功能

`1.0.0` 是项目的首个完整可用版本，已经具备本地收藏管理和桌面端运行所需的核心能力。

- 支持新增、编辑、删除球星卡
- 支持上传卡片图片并进行本地保存
- 支持首页按关键词、运动类型、球队、年份、系列、签名卡、评级状态等条件筛选
- 支持卡片排序，例如按录入时间、年份、价格、评级排序
- 支持卡片详情页查看图片、基础信息、购买信息、评级信息和备注
- 支持展示页浏览全部卡片，并进入单卡展示详情
- 支持 Electron 桌面端运行
- 支持本地 SQLite 数据库存储
- 支持本地图片目录与数据库分离保存
- 支持切换桌面端数据存储路径
- 支持生成 Windows 安装版和便携版发布包

### 1.0.1 升级内容

`1.0.1` 在 `1.0.0` 基础上，主要加强了展示体验、录入稳定性、筛选能力和中文文档质量。

- 展示页球员分组中显示每位球员或组合对应的卡片数量
- 展示页单卡详情保留卡片级切换按钮，并使用英文 `Previous / Next` 区分图片切换
- 首页增加卡片数量显示，并保留总估值统计
- 新增录入页在提交失败后会保留已输入的文字和勾选项，避免整表清空
- 单张卡片图片上限统一为 5 张，并支持新增时一次选择多张图片上传
- 年份支持自由输入，例如 `2016-17`
- “评级机构 / 评级”支持自由输入，适配非纯数字评级场景
- 新增录入页去掉“是否编号卡”勾选项
- 首页筛选去掉“编号卡”，改为 `Patch/Jersey` 筛选
- 清理并统一了一批页面、桌面端提示和文档中的中文乱码
- 重新整理 README 和数据备份说明，便于后续发布到 GitHub

### 1.0.2 升级内容

`1.0.2` 主要补充投入成本相关字段，并修复新增卡片后的成功提示问题。

- 新增“评级费用”字段

- 后端保存时会重新计算总投入，减少前端输入误差
- 卡片详情页在“购买价格”和“当前估值”之间展示“评级费用”和“总投入”
- 修复新增卡片成功后误显示 `NEXT_REDIRECT` 的问题，改为正常显示“添加成功”
- 桌面端安装包和打包版本使用应用图标，并在打包过程中额外写入 Windows 可执行文件图标资源
- 本地 SQLite 初始化和迁移脚本已支持新增字段

## 项目结构

- `app/`：Next.js App Router 页面、详情页、展示页、Server Actions
- `components/`：表单、筛选栏、展示图库、桌面端存储设置等组件
- `lib/`：Prisma 访问、筛选逻辑、展示逻辑、图片路径和存储解析
- `electron/`：Electron 主进程、预加载脚本、本地存储迁移逻辑
- `scripts/`：初始化数据库、准备本地构建、图标生成等脚本
- `prisma/`：Prisma schema 和本地 SQLite 数据库定义
- `public/`：静态资源

## 本地运行

### 1. 安装依赖

```bash
npm install
```

### 2. 生成 Prisma Client

```bash
npm run prisma:generate
```

### 3. 初始化本地数据库

```bash
npm run db:init
```

### 4. 构建 Next.js 应用

```bash
npm run build
```

### 5. 启动桌面端

```bash
npm run electron
```

也可以在 Windows 下直接运行：

```bat
start-desktop.bat
```

说明：使用 `start-desktop.bat` 属于开发态启动方式，任务栏图标可能仍受 Electron 开发运行方式影响。正式安装版和打包版会使用应用图标。

## 发布包说明

项目支持两种 Windows 发布形式，均可在第三方电脑上直接使用，不需要目标电脑再执行 `npm install`。

### 安装版

文件：

- `dist/card-vault-1.0.2-setup.exe`

特点：

- 通过安装向导完成安装
- 可选择安装目录
- 更适合长期在同一台电脑上使用
- 安装完成后可像普通 Windows 软件一样启动

### 便携版

文件：

- `dist/card-vault-1.0.2-portable.zip`

使用方式：

1. 解压压缩包
2. 进入解压后的目录
3. 运行 `card vault.exe`

特点：

- 不需要安装
- 可放在任意文件夹、移动硬盘或 U 盘中运行
- 更适合测试、临时使用或快速分发

### 安装版和便携版的区别

- 安装版适合长期正式使用，便携版适合免安装运行
- 安装版通过 `setup.exe` 安装，便携版通过解压后直接运行
- 两者都可以独立运行，不需要目标电脑安装 Node.js 或项目依赖

说明：

- 当前发布包未进行代码签名，部分 Windows 电脑首次运行时可能出现安全提示
- 这是未签名桌面应用的常见现象，不影响程序本身运行

## 数据存储

项目是本地优先设计。

- 卡片元数据保存在 SQLite 数据库中
- 图片保存在本地 `uploads` 目录中
- 桌面端支持切换“存储路径”

开发态默认数据库位置：

```text
prisma/dev.db
```

桌面端实际运行时，数据通常会使用独立的数据目录，而不是项目根目录里的数据库文件。

详细说明见：

- [数据备份说明](./数据备份说明.md)

## GitHub 仓库与本地运行说明

以下目录或文件通常不建议提交到 GitHub：

- `.env`
- `node_modules`
- `.next`
- `dist`
- 本地数据库文件

原因是它们属于本地配置、依赖安装结果、构建产物或个人数据，不适合作为源码仓库的一部分。

但要注意：

- 这些文件虽然通常不提交到 GitHub
- 对“当前这份本地可直接运行的工作目录”来说，其中一部分是运行必需项
- 例如 `node_modules` 和 `.next` 如果被删除，本地桌面端就无法直接启动，必须重新安装依赖并重新构建

因此建议区分两种使用方式：

- GitHub 仓库用于保存源码、文档和配置
- 安装版 / 便携版用于给第三方电脑直接运行
