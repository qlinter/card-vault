# AI 网络与代理

适用源码版本：v1.5.1。入口为“设置 → AI → 网络与代理”，展开后选择连接方式，最后点击“保存设置”。代理同时用于读取模型、连接测试、识图、文案和组合分析。

## 从零理解连接方案

一次 AI 请求的路径是：本项目 → AI 服务地址。代理是在途中转发请求的服务，使用代理后路径变为：本项目 → 代理 → AI 服务地址。

- **模型**：处理内容的能力名称。同一个模型可能由官方接口、其他服务商或本机服务提供。
- **Endpoint**：实际接收请求的 AI 服务地址。网络是否需要代理，取决于这个地址和当前网络，因此分流按地址判断。
- **代理服务器地址与端口**：转发服务的入口，来自代理软件或服务商，与 AI 的 Endpoint 分别设置。
- **系统代理与规则模式**：代理软件可以向系统提供入口，再按访问的域名决定直连或转发。PAC 是系统按地址选择连接方式的一种规则。

### 适合日常使用的方案

1. 在已有代理软件中开启系统代理，并使用适合当前网络的规则模式。
2. 本项目选择“自动”，保存设置。通常无需在项目中填写代理地址、端口和认证。
3. 项目将 AI 接口地址交给系统规则解析：规则指向代理则转发，规则为直连则直接访问。模型名称不参与这个判断。

有些代理软件让请求先统一进入本机代理，再由软件内部规则决定最终直连还是转发；使用 PAC 时，系统也可以直接给项目返回“直连”或“走代理”。两种情况都可以按服务地址分流，无需逐个模型填写代理。

这种方式让不同 AI 服务按地址分流，也能跟随代理软件更换端口。规则由代理软件或系统提供；单纯安装或打开软件，不一定已经启用系统代理。若当前电脑另有环境变量指定代理，项目会优先采用它们；普通用户通常无需额外设置这些变量。

当前“自动”使用已有配置和规则，不主动探测每个服务的网络可达性。电脑没有提供代理信息时会直连；项目无法凭模型名称推断代理软件端口、账号或该网络下的可达性。接口返回认证、额度或模型权限错误时，也不能据此认定需要代理。

代理软件无法提供系统代理，或使用远程代理网关时，再选择“手动代理”。所有服务均可直接访问时，可以选择“直连”。换设备后先用“自动”，由新设备提供适用的网络规则。

界面只保留配置项、密码保留提示及地址分隔提示；详细说明集中在本页。

| 方式 | 行为与适用环境 |
| --- | --- |
| 自动（默认） | 优先使用当前进程的 HTTP_PROXY、HTTPS_PROXY、ALL_PROXY 和 NO_PROXY；桌面端没有对应环境代理时，按目标地址读取系统代理及 PAC 规则。适合经常更换网络或设备。 |
| 手动代理 | 自行选择 HTTP、HTTPS 或 SOCKS5，填写代理服务器主机名/IP、实际端口和可选用户名、密码。既可使用本机代理软件，也可使用远程网关。 |
| 直连 | AI 请求不使用代理，适合目标服务可直接访问的网络。 |

## 手动设置

1. 从代理软件或代理服务商处取得协议、服务器地址和端口；本项目不预设某个软件、固定端口或本机地址。
2. 协议选择代理服务器本身的协议。代理服务器是 HTTP 时，即使 AI 接口为 HTTPS，也应选择 HTTP。
3. 地址只填写主机名或 IP，协议、端口和认证信息分别填写。支持可选代理用户名及密码，代理密码加密保存，已保存时留空表示保留，也可显式清除。
4. “不经过代理的地址”以逗号分隔，支持精确域名/IP、.example.com、*.example.com、主机:端口、IPv4/IPv6 CIDR 网段（如 192.168.0.0/16、fd00::/8）和 *。网段只匹配地址中直接填写的 IP，不额外解析域名。本地服务默认绕过代理；也可将可直连的 AI 服务加入此列表。
5. 点击“保存设置”。同页的“读取模型”和“测试连接”会使用当前代理草稿，只有主动点击才发起请求。

“测试连接”的结果会简短显示本次线路来自系统规则、环境变量、手动配置或直连/绕过规则，以及实际使用的代理协议；不显示代理地址、用户名或密码。成功仅确认文本请求，不代表所选模型支持识图。代理认证、地址解析、连接拒绝及安全证书问题使用不同提示。更改配置或离开页面会取消当前请求，取消会向上游连接传递；不保证服务商一定停止计费。

OpenAI 的 Endpoint 仍为 https://api.openai.com/v1/chat/completions，不要将其替换为代理软件的本机地址。代理决定连接路径，Endpoint 决定 AI 服务地址。

## 自动模式与开发环境

环境变量支持小写形式，优先级为小写高于同名大写、目标协议的代理高于 ALL_PROXY。HTTPS 请求读取 HTTPS_PROXY，HTTP 请求读取 HTTP_PROXY。支持 http://、https://、socks5:// 与 socks5h:// 形式；地址及端口取当前环境的真实配置。NO_PROXY 规则会绕过代理。

桌面端在没有对应环境代理时通过 Electron 读取系统代理及 PAC 结果，按每次请求的目标地址解析。独立 Node/Web 开发进程无法读取 Electron 系统会话，自动模式没有环境代理时直连；也可通过 CARD_VAULT_AI_PROXY_JSON 配置与界面相同的 mode、protocol、host、port、username、password、noProxy 字段。环境中的凭据由使用者管理，不要提交进源码。

代理连接失败不会自动尝试直连。设置为自动时，只有环境绕过规则、系统明确的 DIRECT 规则，或未配置代理，才会直连。不会修改全局系统代理或其他网络应用。

系统规则目前支持 HTTP、HTTPS、SOCKS5 和 DIRECT。Chromium 的 PAC 格式中，`SOCKS` 与 `SOCKS4` 表示 SOCKS4，不会被误当作 SOCKS5；遇到这些规则时会提示改用受支持的手动配置。详见 [Chromium 代理协议说明](https://chromium.googlesource.com/chromium/src/+/HEAD/net/docs/proxy.md)。多个代理候选按系统提供的顺序使用；仅遇到明确的连接建立或代理握手失败时尝试下一候选，系统明确列出的 DIRECT 才允许直连。TLS 验证失败、连接中断或 AI 接口返回的认证/额度错误不触发候选切换。

接口重定向后会按新地址重新计算线路与绕过规则。跨服务地址跳转会去除原请求的认证及其他私有 Header；不跟随 HTTPS 降级到 HTTP 的地址，不接受带用户名/密码的重定向，最多跟随 10 次。服务依赖跨域认证时应直接填写最终 Endpoint。

## 设备与凭据

代理设置保存在当前设备的 AI 用户配置中，不写入收藏数据库，也不随收藏备份、CSV/XLSX 或分享包迁移。换设备后建议先使用自动模式，或填写新设备适用的代理信息；手动复制加密配置可能需要重新输入密码。登录凭据不用于日志，模型接口错误中的 API Key 会被遮蔽。

已保存凭据暂时无法解密时，保存其他设置仍保留原密文，并继续显示恢复提示。仅明确提交新凭据或清除操作才替换对应密文；加密不可用时不能保存新密码。此规则同时适用于内置服务、自定义服务、旧 Azure 配置迁移及代理密码。

验证使用本机模拟服务，覆盖 HTTP、HTTPS、SOCKS5、HTTPS 目标的隧道连接、特殊字符认证、TLS 验证、环境变量、绕过网段、系统候选切换、逐次重定向和取消。HTTPS 测试仅在独立测试子进程中信任仓库的测试证书，没有关闭生产证书校验。`npm run test:proxy:pac` 使用真实 Electron 的隔离会话读取本机 PAC，验证 HTTP/HTTPS/SOCKS5/DIRECT 及候选顺序，不修改 Windows 系统代理。桌面生产服务中的模型列表与连接测试路由也经本机代理验证，包括用户取消后关闭上游连接。界面覆盖中英文、结果提示和 320px 窄窗口。未连接外部 AI，未逐台验证其他设备和代理软件，安装包及实际设备验收单独执行；完整源码结果见[项目审查与验收](./assessment-2026-11-03.md)。
