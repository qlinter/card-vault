# Card Vault

简体中文 | [English](./README.en.md)

Card Vault 是一款本地优先的球星卡收藏管理工具，用于录入、整理、检索、展示和分享个人收藏。项目基于 `Next.js + React + Prisma + SQLite + Electron`，卡片数据与图片默认保存在本机，可离线使用。

## 当前版本

`1.0.11`

### 1.0.11 重点更新

- 数据库升级改为有序迁移，接管旧数据库前自动生成快照，降低跨版本升级风险。
- 设置页增加数据健康检查、未引用文件明细与资源管理器定位、确认清理、完整备份和应用内恢复。
- AI API Key 使用 Windows `safeStorage` 加密；旧密钥无法解密时不再阻断程序启动，并提示重新输入。
- 首页增加 AI 组合分析，仅发送经过白名单过滤的汇总数据，不发送图片和私人备注。
- 修复开发版可能复用残留本地服务的问题；现在每次启动独立服务，退出时清理完整进程树。
- 修复开发版 preload 桥接异常、AI 设置误判非桌面环境、分享主题显示 `Failed to fetch` 等问题。
- 修复分享集编辑后保存无反馈的问题，保留原生 Server Action 并增加保存状态与校验提示。
- 发布流程统一执行编码、类型、单元测试、生产构建、卡片与分享 E2E、打包运行时验证和 SHA-256 计算。

## 核心功能

- 球星卡新增、编辑、删除、详情查看和最多 5 张图片管理。
- 按球员、运动、球队、年份、产品线、评级、签名、Patch、状态等字段搜索、筛选和排序。
- 记录购买价格、评级费用、总投入、当前估值、评级信息、收藏状态和公开状态。
- 展示页按球员或组合浏览收藏，支持分组收起、卡片切换和单卡多图切换。
- 使用 Azure OpenAI 或 MiniMax 进行 AI 识图录入、分享文案生成和组合分析。
- 创建可编辑的分享展馆，配置主题、布局、章节、封面、背景和单卡展示内容。
- 导出可独立打开的静态分享包和服务器静态托管包。
- 本地 SQLite 存储、可切换数据路径、独立备份路径、健康检查和恢复。
- 提供 Windows 安装版与便携 ZIP，目标电脑无需安装 Node.js。

## 安装与运行

### 安装版

文件：`dist/card-vault-1.0.11-setup.exe`

- 使用安装向导，可选择安装目录，适合长期使用。
- 安装较早版本后可直接安装同一应用的新版本，通常会覆盖程序文件，不会主动删除收藏数据。
- 当前发布包未进行代码签名，Windows 首次运行时可能显示安全提醒。

### 便携版

文件：`dist/card-vault-1.0.11-portable.zip`

1. 完整解压 ZIP。
2. 运行解压目录中的 `Card Vault.exe`。
3. 不要只移动 EXE；程序依赖同目录下的完整运行文件。

便携版适合临时使用、测试、移动硬盘和快速分发。它不是“单文件绿色软件”，ZIP 解压后才是完整运行目录。

### 本地开发

首次准备：

```bash
npm install
npm run db:init
npm run build
```

Windows 桌面启动：

```bat
start-desktop.bat
```

也可以运行：

```bash
npm run electron
```

开发版使用 `%APPDATA%\Card Vault Development` 保存桌面配置。首次切换时只继承旧开发配置中的数据路径和 AI 设置，不移动或清洗卡片数据。

## 数据与备份

Card Vault 的数据由 SQLite 数据库和媒体目录共同组成：

- `dev.db`：卡片、分享集和设置关联数据。
- `uploads`：卡片图片。
- `share-covers`：分享集封面。
- `share-backgrounds`：分享集背景。
- `schema-backups`：数据库迁移前快照。

设置页支持：

- 更改当前数据存储路径。
- 在“存储数据”中检查 SQLite 完整性、缺失文件和未引用文件。
- 查看未引用文件明细、在资源管理器中定位文件，并在二次确认后清理。
- 设置独立备份路径并执行一键备份。
- 使用“备份恢复”恢复数据；可选择日期文件夹或其中的具体 data 文件夹，恢复前会自动创建当前数据的安全备份。

更换电脑或重装前，请使用设置页备份功能迁移完整数据，不要只复制数据库或只复制图片。详细说明见 [数据备份说明](./数据备份说明.md)。

## AI 功能

- 全局 AI 设置位于“设置 → AI 设置”，支持 Azure OpenAI 和 MiniMax。
- AI 设置由识图录入、分享文案和组合分析共用。
- API Key 保存在本机用户配置目录，并通过 Windows `safeStorage` 加密，不写入 Git、数据库或发布包。
- 如果 Windows 环境无法解密旧密钥，程序会继续启动并保留 Endpoint、部署和模型；请重新输入一次 API Key 后保存。
- AI 识图支持 1 至 2 张正反面 `jpg/png/webp` 图片，默认只填充空字段。
- 组合分析仅发送当前筛选结果的统计摘要，结果用于收藏整理参考，不构成投资或交易建议。
- AI 服务无法连接时会区分本地服务问题和上游网络、Endpoint、代理或服务商错误。

## 分享展馆

- 分享集与本地展示页相互独立，只包含用户主动选择的卡片。
- 可编辑标题、介绍、叙事、章节、主题、布局、封面、背景和单卡展示覆盖。
- 内置通用、运动和球队主题，预览、静态包和云端发布包使用同一套渲染结果。
- 静态导出采用公开字段白名单，不包含价格、成本、购买渠道、私人备注、AI Key 或本地路径。
- 云端发布包提供静态服务器部署说明；当前项目尚未实现应用内一键上传、更新和撤回。

## Git 与目录说明

GitHub 主要同步源码、文档和配置，不应提交个人数据与本机构建环境。`.gitignore` 默认忽略：

- `.env` / `.env.local`：可能包含 API Key 和本机配置。
- `node_modules`：可由 `npm install` 重新生成，体积很大。
- `.next`：可由 `npm run build` 重新生成。
- `data`、本地数据库和上传图片：属于个人收藏数据。
- `logs` 和缓存：仅用于本机运行与排错。

`dist` 是否提交由仓库发布策略决定。更推荐将安装版和便携 ZIP 上传至 GitHub Releases，并让源码仓库保持精简。

## 项目结构

- `app/`：页面、API 路由和 Server Actions。
- `components/`：表单、筛选、设置和展馆组件。
- `lib/`：数据库、AI、图片、统计和导出逻辑。
- `electron/`：桌面主进程、preload、存储与 AI 配置。
- `prisma/`：数据库结构。
- `scripts/`：迁移、检查、测试和发布脚本。
- `tests/`：业务规则、数据安全和导出回归测试。
