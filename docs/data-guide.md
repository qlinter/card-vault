# 数据管理与备份

设置 → 数据集中提供备份与恢复、导入与导出、存储维护。收藏页导出复用当前筛选与选卡结果；设置页可导出全部。统计和资料整理见[统计规则](./data-analysis-guide.md)，心愿操作见[收藏指南](./collection-guide.md#wishlist)。

## 导入与档案更新

手动录入提供保存保护：同一次提交重试返回首次保存结果，同一草稿或队列项目只建立一份档案；新开空白录入仍可保存同款独立实物。提交前草稿同步失败时保留输入，待重试成功后再保存。

删除确认页打开后，档案、图片、财务或关联记录若发生变化，删除会被拒绝并返回详情页；请核对最新内容后重新打开删除确认页。核对与删除在同一事务内完成，拒绝删除时保留关联数据与媒体文件。

普通上传在保存前解码校验 JPG、PNG、WebP，最多 8000 万输入像素；损坏或截断文件被拒绝，合法文件保留原始字节。历史文件不自动重写。

编辑表单读取后，档案或图片若被其他操作更新，保存会报告冲突并保留当前输入及已选图片。请先核对最新资料，再重新打开编辑页继续处理；财务操作引起的状态变化在同页同步，其他未保存档案输入继续保留。财务表单校验失败后，后续纠正不会被延迟回填覆盖。

1. 选择 UTF-8 CSV 或 XLSX 文件。XLSX 使用第一个工作表，公式须先转换为明确数值；每批最多 10 MB、10000 行、80 列。
2. 将文件表头映射到卡片字段，忽略不需要的列。编号应在电子表格中保存为文本，以保留前导零。界面显示第一行样例。
3. 选择重复策略：默认跳过；更新只修改映射到的档案字段；“独立实物”明确新增另一张卡片。卡片 ID 优先匹配，其次证书号，再以主体、名称、运动、年份、平行版本和实物编号组合匹配。多重匹配必须提供 ID。
4. 建立预演，检查逐行字段、匹配 ID 和错误。预演不会创建或修改卡片。新档案允许暂不带图片，后续由整理提醒补齐。
5. 执行后保留每行结果。每 50 行提交一个请求，每行独立事务；重复提交不会重复执行已完成的行。当前批次可继续执行或重试；“最近批次”列表已按界面要求移除，收起设置中的数据分类仍保留本页输入及批次状态。

新卡初始价格、日期、数量和估值写入正式财务流水；已有卡片导入不覆盖财务历史或改变持仓状态。持仓状态与交易数量仍在详情页维护。

收藏页通过现有筛选和列表选择导出卡片；已移除修改字段及其批量修改预演入口。档案修改可使用文件导入的更新策略，财务记录在卡片详情页维护。

“撤销本批次”需要在界面确认：新增卡片将删除，档案修改将恢复原值。系统对档案、流水、图片和分享引用检查操作后的指纹；已有后续修改时保留数据并报告冲突。可使用“重新建立预演”根据当前数据建立新批次。无效原始数据需要修正文件后再导入。

导入和导出面板只保留操作与结果，格式限制、数据范围和备份边界等说明统一放在设置页尾“帮助与版本”中的“使用说明”。

## 导出与换机

收藏页开启导出后，卡片信息仍可打开详情；返回上一页会恢复原筛选、已加载卡片、网格或列表视图、公开导出选项与勾选。选择只属于当前精确的筛选地址，不会转移到其他范围。

有勾选时，CSV/XLSX 仅导出已应用筛选范围内选中的卡片，支持加载更多后继续勾选、选中已加载卡片或选择全部匹配结果；无勾选时导出当前筛选全部结果。界面显示已选数量或当前范围。“仅导出公开档案”始终叠加过滤私密卡片与字段。选中的卡片已删除或被公开过滤排除时，不会扩大导出范围。

- CSV 导出当前筛选范围的档案字段，适合整理和外部核对。可能触发电子表格公式的文本会添加单引号前缀。
- 私密 XLSX 的 `Cards` 工作表保存档案，`Financial history` 单独保存原币交易、费用、估值和付款组成；财务页用于核对，不能作为档案字段回灌。
- “仅导出公开档案”只包含公开卡片，排除私密备注和财务流水。
- 图片、草稿、分享配置、批次和全部历史的无损迁移仍使用设置中的完整备份与恢复。CSV/XLSX 不是数据库备份格式。

备份清单、恢复报告和孤立媒体恢复副本的规则统一见[数据备份说明](#backup)。

批次仅接受当前文件导入格式；已退役的档案修改/估值批次不再提供读取、执行、撤销或重新预演入口。

## 完整备份、恢复与存储

### 1. 数据保存位置

Card Vault 的收藏数据由以下内容共同组成：

- `dev.db`：卡片、财务历史、录入草稿、模板、批量队列、分享集、报表设置、人工汇率修订、导入批次、心愿单、提醒状态及摘要周期。已有数据库可能含已停用功能的额外表，当前程序忽略其内容，不自动删表或清空。
- `uploads`：卡片图片、已经完成预处理的队列 WebP，以及录入草稿图片。
- `thumbnails`：首页使用的可重建 WebP 缩略图缓存，不属于必须备份的收藏原始数据。
- `entry-queue`：批量录入队列中尚待处理或可重试的源图片。
- `share-covers`：分享集自定义封面。
- `share-backgrounds`：分享集自定义背景。

心愿编辑草稿与寻卡窗口上下文保存在本机浏览器存储，不在上述数据库备份内；数据库中的录入草稿仍包含在备份中。心愿仅保存独立名称、主体、预算及备注，不提供关键词关系或多卡绑定。Git 同步源码不迁移个人收藏。

恢复和页面访问均不再执行旧寻卡、心愿、分析快照或回顾历史的自动清理。正常的心愿编辑、用户主动删除及数据健康工具保持原有行为。

普通录入草稿会一并保存选中的图片和旋转状态；重新打开草稿会恢复文件选择。完成录入或删除草稿后清理其临时图片。草稿图片受数据健康检查保护，不会被当作未引用图片清理。分享编辑草稿按当前收藏库隔离，保存在浏览器存储中，不随数据库备份迁移。

桌面端默认数据目录通常是：

```text
C:\Users\<你的用户名>\AppData\Roaming\Card Vault\data
```

如果在“设置 → 数据 → 维护 → 存储”中修改过路径，请以设置页显示的路径为准。

### 2. 推荐备份方式

“设置 → 数据 → 备份与恢复 → 一键备份”会暂停本地数据服务，待进程退出后复制原始媒体并生成 SQLite 一致性快照，检查数据库完整性和媒体引用；缺失引用文件则清理本次不完整备份并报告失败，完成或失败后恢复服务。可由原图重建的 `thumbnails` 缓存不会进入备份。该方式无需退出程序，也是日常备份与换机前备份的首选。

如需压缩归档，请压缩一键备份生成的完整目录，保留校验清单。退出程序后直接复制的数据目录可用于原样保存，但不带清单的副本不接受应用内备份恢复；不要只复制数据库或只复制图片。

一键备份会按日期创建目录；同一天多次备份会生成独立 data 子目录，不覆盖已有备份。

备份前估算所需空间并保留额外余量；恢复在复制当前数据安全副本和暂存数据前分别检查目标磁盘空间。设置页显示当前收藏库最近一次成功备份的时间、大小、图片文件数、创建时校验状态及文件是否仍可用；超过 7 天会提示重新备份。该状态记录不替代恢复前的完整校验。

备份由用户点击“一键备份”发起，不执行定时备份或自动清理历史副本；已有副本不因创建方式不同而删除，能否恢复取决于当前格式和清单校验。恢复前创建当前数据的安全副本。成功读取备份设置且尚无成功备份记录时，设置页显示“当前收藏库尚无成功备份记录。”；加载中、读取失败或无桌面备份接口时不显示此状态，首次成功备份后显示最近备份信息。

新备份写入 `backup-manifest.json`，包含应用版本、全部数据表数量、文件大小及 SHA-256。恢复前核对完整文件清单与表数量；不接受缺失或不一致的清单。无清单或非当前数据库结构的备份直接拒绝，不补表。恢复在暂存区写入 `restore-report.json`，记录校验结果、结构版本、恢复后数量和安全备份位置，再重建暂存副本清单；不转换分类或修改业务记录，来源备份保持原样。

### 3. 从备份恢复

1. 展开“设置 → 数据”，找到“备份与恢复”。
2. 点击“备份恢复”。
3. 选择一键备份生成的日期文件夹，或直接选择其中包含 `dev.db` 的 data 文件夹；日期文件夹中存在多次备份时，程序会使用最新的一份。
4. 确认恢复。程序会先备份当前数据，再将来源复制到暂存目录。
5. 来源及复制后的暂存副本均校验备份清单的文件数量、大小、SHA-256 与记录数，以及完整结构、索引、触发器、估值来源约束、状态记录、SQLite 完整性及关联完整性。通过后生成恢复报告和清单，再执行目录切换。恢复不修改数据库结构或业务记录，来源备份保持原样。
6. 恢复成功后本地数据服务会在应用内重新连接，当前页面自动刷新并加载备份数据；Electron 应用不会退出或重启。

暂存验证失败时不会替换当前数据；目录切换失败或切换后的最终布局/完整性检查失败会尝试恢复保留目录；最终检查成功后才清理临时原目录。临时原目录清理失败时保留其路径，不把成功恢复误报为失败。安全备份持续保留，发生服务重连失败时应依据提示和日志处理，不能将其视为完整恢复成功。

目录切换前写入独立恢复操作记录，并刷新到磁盘。进程突然退出后，下次启动在创建数据目录之前检查该记录：最终校验尚未完成时恢复原目录，已完成时保留新目录；不会把恢复中缺失的目录初始化为空收藏。中断的暂存副本保留用于检查。模拟进程退出测试覆盖原目录移动后、新目录切换后和最终验证后三个边界；这不等同于物理断电测试。

### 4. 当前数据库基线边界

- 新建空数据库一次性创建完整结构。v1.5.1 的完整数据库可以直接使用；已有库仅校验，不执行旧版结构升级、分类转换、补表补列、状态回填或历史删除。回顾按当前记录计算，无需新增保存表。
- 管理设置只保留摘要周期；新库不再创建退役通知字段和卡片人民币摘要字段，Prisma 不再读取或写入这些字段，财务记录由流水保存。已有库中的额外列不删改，也不解释为可用功能。
- 当前格式包括财务、管理、状态跟踪、财务索引队列和寻卡结构；仅有相同产品版本号不足以判定兼容。缺表、缺字段、缺索引/触发器或状态记录不完整时拒绝启动和恢复，原数据库保持不变。
- 备份必须带有有效的 `backup-manifest.json`；只接受完整的当前格式，早期不完整格式和无清单备份不支持。恢复报告使用 `restore-report.json`。
- 应用不会替换或转换历史卡片原图。普通单卡上传继续保留原格式，批量录入队列的新图片仍按既定规则预处理为 WebP；首页会为首图另行生成最长边 640px 的 WebP 缩略图缓存。

### 5. 更换存储路径

- 更换路径会由独立存储进程把完整数据复制到暂存目录，`dev.db` 使用 SQLite 一致性快照，校验通过后才切换路径并重启应用。
- 新目标必须是空文件夹或可识别的 Card Vault 数据目录；程序不会覆盖无关的非空目录。
- 选择已有 Card Vault 数据的目录时，程序会先检查当前数据库格式与完整性；失败时保留原存储配置并恢复本地服务。
- 存储路径移动与数据库版本升级是两件事。移动路径不会改变卡片内容或数据库结构。

### 6. 数据健康与清理

- “检查数据健康”会检查 SQLite 完整性、数据库引用但本地缺失的媒体，以及本地存在但未被引用的媒体。
- 卡图及队列成品仅接受 `/media/` 当前地址，不再转换 `/uploads/` 旧地址。路径格式无效时健康检查失败，清理被拒绝，不移动或删除文件。
- 健康检查本身只读取数据；未引用文件可在资源管理器中定位。
- “清理未引用文件”会二次确认并重新检查，暂停本地服务并复核数据库引用，将仍未被引用且位于受管媒体目录中的文件移至数据目录 `.recovery`，保留相对路径。没有自动清空或一键还原入口；需要找回时核对恢复副本，建议处理前先完整备份。
- `entry-queue` 源图、队列 WebP、分享封面和分享背景都在备份、恢复、健康检查及清理边界内。

### 7. 换机检查清单

- 在旧电脑设置页执行一次“一键备份”。
- 确认备份目录同时包含 `dev.db`、相关媒体目录和 `backup-manifest.json`。
- 在新电脑安装同一当前版本后，通过“备份恢复”导入。
- 恢复完成并自动刷新后，检查卡片数量、图片、财务历史、草稿、模板、批量队列、分享背景、导入批次、心愿单和提醒状态。
- 确认无误前，不要删除旧电脑或外部存储上的最后一份完整备份。

存储路径和加密 AI 配置共用完整替换写入：临时文件写完并刷新后再替换原文件，写入或替换失败保留原配置。此机制不替代完整数据备份。

## 导出资源与规模边界

CSV/XLSX 先生成一致的 SQLite 临时快照，按每批最多 250 条读取卡片及各类财务记录；CSV 按行写入，XLSX 按工作表写入 XML 后流式压缩，不在内存中构造整本工作簿。文件完整生成后开始下载，每块 64 KiB，并限制下载队列。大文件需要等待生成，且临时磁盘需要容纳数据库快照、工作表及最终文件。正常完成、取消和异常会关闭句柄并清理该任务目录；强制结束进程的残留文件仍由系统临时目录管理。

每个服务进程最多同时进行两个导出，卡片导出共用此额度及快照、超时、下载取消和清理流程；生成最长 10 分钟，数据库快照最长 30 秒。XLSX 每表最多 1,048,576 行（含表头），超出后建立带序号的工作表并重复表头。选中导出最多 10000 张，无勾选的搜索结果导出没有此选择上限；导入仍限制为 10 MB、10000 行、80 列，只读取第一张表。公开过滤、CSV 文本转义和财务口径沿用原规则。简化寻卡不再提供独立关键词或心愿 CSV 清单导出；卡片 CSV/XLSX 导入导出及完整备份格式保留。

性能基准命令见[开发维护](./development.md#checks)。旧规模测试的机器条件、观测数值与限制已移至[历史基准](./history/development.md#data-benchmarks)，不作为当前版本的性能承诺。
