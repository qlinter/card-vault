# 财务历史数据模型

适用版本：`1.1.0`。数据模型沿用 v1.0.14 建立的历史事实口径。

## 目标

历史数据模型将“当前卡片快照”与“随时间发生的事实”分开保存，为后续交易记录、费用分析、估值曲线和已实现收益提供可靠基础。

## 模型

### `CardTransaction`

记录购买、出售和退款：

- `kind`：`purchase`、`sale`、`refund`
- `amountMinor`：最小货币单位整数，例如人民币或美元 100.25 保存为 `10025`
- `currency`：仅允许 `CNY` 或 `USD`
- `quantity`、`occurredAt`、`source`、`notes`
- `provenance`：数据来源，例如 `manual` 或 `legacy_card_snapshot`
- `externalKey`：导入或迁移时的幂等键

### `CardExpense`

记录评级、运输、税费、保险、仓储、平台费及其他费用。金额、币种、发生时间、来源和幂等规则与交易记录一致。

### `CardValuation`

记录某个时间点的估值：

- `amountMinor`、`currency`
- `valuedAt`
- 必填 `source`，只能选择“个人估计”“近期成交”“平台报价”
- `notes`、`provenance`、`externalKey`

## 可靠性规则

- 金额不再使用浮点数作为历史事实，统一按币种的小数位规则转换为整数最小货币单位。
- 不同币种不直接相加；汇率换算必须由后续独立模型明确记录。
- 迁移 `008_limit_financial_currencies_v1_1_0` 会删除非 CNY/USD 的旧财务记录，并在数据库层拒绝后续写入其他币种。
- 数据库约束拒绝负金额、非法交易/费用类型、非三位大写币种及非正交易数量。
- 历史记录随卡片删除而级联删除。
- 交易、费用和估值按卡片与业务时间建立倒序索引。
- `provenance` 必填；估值 `source` 必填。
- `externalKey` 唯一，供旧数据回填和未来导入幂等使用。

## 旧数据迁移

迁移 `006_card_financial_history_v1_1_0` 会为旧卡片生成基线记录：

- `purchasePrice` → `purchase` 交易
- `gradingFee` → `grading` 费用
- `currentValue` → 估值

这些记录标记为 `legacy_card_snapshot`，并使用稳定 `externalKey`，因此重复执行不会制造重复历史。迁移 `007_normalize_valuation_sources_v1_1_0` 会把所有已存在估值的来源统一设为“个人估计”。旧字段暂时保留给尚未迁移的旧版统计和兼容流程；首页总估值与组合分析均直接读取历史记录，不再把这些 CNY 快照作为事实来源。

## v1.1.0 当前使用方式

卡片新增页的“初始财务记录”会分别建立购买交易、评级费用和初始估值；估值必须同时填写日期与来源。普通卡片编辑页只编辑卡片资料，不覆盖或自动追加财务历史。

卡片详情页提供：

- 按 CNY/USD 分别汇总购入、费用、售出和最新估值
- 新增交易、费用和估值
- 按业务日期合并的时间线
- 单条记录纠错及删除

所有新增、纠错和删除都与兼容快照的重新计算放在同一数据库事务内。只有 CNY 记录进入旧版快照字段，避免混合币种；完整的 CNY/USD 事实始终以历史表为准。首页针对当前筛选结果直接读取每张卡业务日期最新的一条估值，不使用兼容快照，也不会重复累计旧估值。
