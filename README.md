# Card Vault

简体中文 | [English](./README.en.md)

Card Vault 是一款本地优先的球星卡收藏管理工具，用于录入、整理、检索、展示和分享个人收藏。项目基于 `Next.js + React + Prisma + SQLite + Electron`，卡片数据与图片默认保存在本机，可离线使用。

## 当前版本

`1.0.14`

### 1.0.14 重点更新

- 完成分享展馆编辑器 2.0：四区工作台、拖拽与键盘排序、撤销/重做、本机草稿恢复、封面和背景即时预览，以及字体、密度和图片构图设置。
- 修复应用内分享预览点击单卡后加载完整 Card Vault 界面的问题；预览改为内嵌单卡详情。
- 合并分享包导出入口，提供通用静态包和 Cloudflare Drop 临时预览包，并增加公开字段、断链、文件数量和 25 MiB 单文件检查。
- 建立交易、费用和估值历史，支持新增、时间线、按币种汇总、纠错和删除；旧财务字段仅作为 CNY 兼容快照。
- 财务币种限定为 CNY/USD，估值来源限定为个人估计、近期成交或平台报价；旧数据和恢复的旧备份自动迁移。
- 首页总估值改为对当前筛选结果逐卡采用最新估值，CNY/USD 分行并使用统一字号、ISO 代码和千位分隔符，覆盖度采用简略显示。
- 首页组合分析改为直接汇总交易、费用与最新估值历史，按 CNY/USD 分币种展示成本、净现金占用、可比未实现盈亏、估值时效及来源，不进行隐含汇率换算。
- 备份恢复会先在暂存目录完成所有待办迁移和完整性检查，成功后才替换当前数据。
- 桌面启动脚本会检查依赖是否缺失或落后于锁文件，并在需要时自动完成安装。
- Windows 正式发布启用强制 Authenticode 签名、SHA-256 RFC 3161 时间戳和打包后签名验证，阻止未签名安装器被误发布。

## 核心功能

- 球星卡新增、编辑、删除、详情查看和最多 5 张图片管理。
- 按球员、运动、球队、年份、产品线、评级、签名、Patch、状态等字段搜索、筛选和排序。
- 以交易、费用和估值历史记录购入、售出、退款、评级及其他成本，并维护最新估值。
- 展示页按球员或组合浏览收藏，支持分组收起、卡片切换和单卡多图切换。
- 使用 Azure OpenAI 或 MiniMax 进行 AI 识图录入、分享文案生成和组合分析。
- 创建可编辑的分享展馆，配置主题、布局、章节、封面、背景和单卡展示内容。
- 导出通用静态分享包或 Cloudflare Drop 临时预览包。
- 本地 SQLite 存储、可切换数据路径、独立备份路径、健康检查和恢复。
- 提供 Windows 安装版与便携 ZIP，目标电脑无需安装 Node.js。

## 安装与运行

### 安装版

计划文件：`dist/card-vault-1.0.14-setup.exe`（等待确认后生成）

- 使用安装向导，可选择安装目录，适合长期使用。
- 安装较早版本后可直接安装同一应用的新版本，通常会覆盖程序文件，不会主动删除收藏数据。
- v1.0.14 起正式发布必须使用受信任的 Windows Authenticode 证书签名，并附带 SHA-256 RFC 3161 时间戳；发布脚本会验证安装器和主程序签名，未签名时拒绝生成发布结果。
- 普通 OV 证书在建立 SmartScreen 信誉前仍可能短期显示提示；希望新证书尽快获得公开信任时，优先使用 EV 证书或 Microsoft Artifact Signing。

### 便携版

计划文件：`dist/card-vault-1.0.14-portable.zip`（等待确认后生成）

1. 完整解压 ZIP。
2. 运行解压目录中的 `Card Vault.exe`。
3. 不要只移动 EXE；程序依赖同目录下的完整运行文件。

便携版适合临时使用、测试、移动硬盘和快速分发。它不是“单文件绿色软件”，ZIP 解压后才是完整运行目录。

### 本地开发

首次准备：

```bash
npm install
npm run db:init
npm run build
```

Windows 桌面启动：

```bat
start-desktop.bat
```

也可以运行：

```bash
npm run electron
```

开发版使用 `%APPDATA%\Card Vault Development` 保存桌面配置。首次切换时只继承旧开发配置中的数据路径和 AI 设置，不移动或清洗卡片数据。

## 数据与备份

Card Vault 的数据由 SQLite 数据库和媒体目录共同组成：

- `dev.db`：卡片、分享集和设置关联数据。
- `uploads`：卡片图片。
- `share-covers`：分享集封面。
- `share-backgrounds`：分享集背景。
- `schema-backups`：数据库迁移前快照。

设置页支持：

- 更改当前数据存储路径。
- 在“存储数据”中检查 SQLite 完整性、缺失文件和未引用文件。
- 查看未引用文件明细、在资源管理器中定位文件，并在二次确认后清理。
- 设置独立备份路径并执行一键备份。
- 使用“备份恢复”恢复数据；可选择日期文件夹或其中的具体 data 文件夹，恢复前会自动创建当前数据的安全备份。
- 备份、恢复、健康检查和清理在独立存储进程执行；设置页会显示当前阶段与进度，桌面主界面可继续响应。

更换电脑或重装前，请使用设置页备份功能迁移完整数据，不要只复制数据库或只复制图片。详细说明见 [数据备份说明](./docs/data-backup-guide.md)。

## AI 功能

- 全局 AI 设置位于“设置 → AI 设置”，支持 Azure OpenAI 和 MiniMax。
- AI 设置由识图录入、分享文案和组合分析共用。
- API Key 保存在本机用户配置目录，并通过 Windows `safeStorage` 加密，不写入 Git、数据库或发布包。
- 如果 Windows 环境无法解密旧密钥，程序会继续启动并保留 Endpoint、部署和模型；请重新输入一次 API Key 后保存。
- AI 识图支持 1 至 2 张正反面 `jpg/png/webp` 图片，默认只填充空字段。
- 组合分析仅发送当前筛选结果的统计摘要，结果用于收藏整理参考，不构成投资或交易建议。
- AI 服务无法连接时会区分本地服务问题和上游网络、Endpoint、代理或服务商错误。
- Azure OpenAI 统一使用 `v1` API；Endpoint 可填写资源根地址（`.openai.azure.com` 或 `.services.ai.azure.com`），Deployment 填写 Azure 中实际创建的部署名称。
- GPT-5.4 / GPT-5.5 / GPT-5.6 请求统一使用 `/openai/v1/chat/completions`，不再保留日期式 `api-version` 配置；GPT-5 reasoning 模型请求不会发送不受支持的 `temperature` 参数。

## 分享展馆

- 分享集与本地展示页相互独立，只包含用户主动选择的卡片。
- 编辑器 2.0 将标题与介绍、视觉设计、展馆章节和单卡展示拆分为四个工作区，并保留随编辑同步更新的预览。
- 实时预览支持桌面和手机宽度切换；预览、静态包和 Cloudflare Drop 临时发布包继续共用同一渲染器。
- 可编辑标题、介绍、叙事、章节、主题、布局、封面、背景和单卡展示覆盖。
- 内置通用、运动和球队主题，预览、静态包和 Cloudflare Drop 临时发布包使用同一套渲染结果。
- 静态导出采用公开字段白名单，不包含价格、成本、购买渠道、私人备注、AI Key 或本地路径。
- Cloudflare Drop 临时发布包提供断链、私密字段、文件数量和单文件大小检查，并附带 noindex、404、内容清单和一小时临时发布说明。
- Card Vault 不记录 Drop 临时 URL 或认领链接；永久发布、更新、撤回和线上验证留待正式托管接入后实现。

编辑器 2.0 的边界、当前实现与后续阶段见 [分享展馆编辑器 2.0 说明](./docs/share-editor-2.0.md)。
Cloudflare Drop 的发布边界和包内检查见 [Cloudflare Drop 临时发布说明](./docs/cloudflare-drop-publishing.md)。
历史表结构、约束与旧数据迁移策略见 [财务历史数据模型](./docs/financial-history-model.md)。

## 财务历史

- 新增卡片时，“初始财务记录”会分别建立购买交易、评级费用和初始估值。
- 卡片资料编辑不会覆盖财务历史；交易、费用与估值统一在卡片详情页维护。
- 详情页支持 CNY/USD 独立汇总、统一时间线、单条纠错和删除；估值来源限定为“个人估计”“近期成交”“平台报价”。
- 旧版财务字段仅作为尚未迁移流程的 CNY 兼容快照，由历史记录自动重新计算；首页总估值和组合分析都直接读取财务历史。
- 首页“总估值”针对当前筛选出来的全部卡片，每张只采用业务日期最新的一条估值；CNY/USD 统一采用相同字号的 ISO 代码格式显示，不会按收藏状态排除，也不会重复累计历史估值。
- 首页“组合分析”按 CNY/USD 分别汇总真实交易、费用和最新估值，展示活跃成本基础、净现金占用、可比未实现盈亏、估值时效及来源，不会隐含换算汇率或虚构已实现收益。
- 从备份恢复旧数据库时，会先在暂存目录执行全部待办迁移并通过完整性检查，再替换当前数据；因此旧备份中的估值来源也会统一迁移为“个人估计”。

## Git 与目录说明

GitHub 主要同步源码、文档和配置，不应提交个人数据与本机构建环境。`.gitignore` 默认忽略：

- `.env` / `.env.local`：可能包含 API Key 和本机配置。
- `node_modules`：可由 `npm install` 重新生成，体积很大。
- `.next`：可由 `npm run build` 重新生成。
- `data`、本地数据库和上传图片：属于个人收藏数据。
- `logs` 和缓存：仅用于本机运行与排错。

`dist` 是否提交由仓库发布策略决定。更推荐将安装版和便携 ZIP 上传至 GitHub Releases，并让源码仓库保持精简。

Windows 正式发布需要先配置代码签名凭据。PFX、证书存储/EV 和 Microsoft Artifact Signing 的配置及验证方式见 [Windows 代码签名说明](./docs/windows-code-signing.md)。证书文件和密码不得写入仓库或 `.env`。

## 项目结构

- `app/`：页面、API 路由和 Server Actions。
- `components/`：表单、筛选、设置和展馆组件。
- `lib/`：数据库、AI、图片、统计和导出逻辑。
- `electron/`：桌面主进程、preload、存储与 AI 配置。
- `prisma/`：数据库结构。
- `scripts/`：迁移、检查、测试和发布脚本。
- `tests/`：业务规则、数据安全和导出回归测试。
