## 本地账户与恢复

账户属于本机应用配置，与收藏库独立。首次使用创建用户名与 8–128 个字符的密码，保存恢复码后进入原有收藏。桌面配置中的 `account.json` 和 `account.json.initialized` 保存密码哈希、恢复码摘要及初始化状态；请勿手动删除或编辑。开发版使用独立开发配置；通过 `npm start` 打开的本地网页版使用操作系统配置目录下的 `Card Vault Web`，不共用桌面账户。

收藏完整备份、CSV/XLSX 及分享导出不携带账户。恢复收藏不会覆盖登录凭据；换机应先建立该设备自己的账户，再恢复收藏。若需保留本机账户恢复能力，可另外妥善保存上述两个账户文件；它们不属于收藏备份。保存恢复码即可在忘记密码时重设密码，使用后需保存新码；旧码立即失效。用户名可在恢复成功后查看。

收藏路径必须与本机应用配置分开，不能选择包含应用配置目录的文件夹作为收藏根目录。这样可避免账户被带入收藏备份，或在恢复收藏时被替换。

### 访客浏览

主人可在「设置 → 账户与安全」开启「允许访客浏览」，并查看可浏览的公开卡牌数量。访客入口默认关闭。开启后可从登录页进入，也可在账户设置中点击「进入访客浏览」，结束当前主人会话并交接到展墙。「退出访客」返回登录页。

访客可搜索、分组、查看公开卡牌的大图及使用浏览展馆。访客展墙、单卡详情、原图与缩略图均按当前公开状态取数。私密或仅链接可见的卡牌、私人备注、财务、统计、分享管理、导出及设置需要主人登录。访客的网格与展馆偏好独立保存。Windows 锁屏或完整重启应用后，需重新进入访客浏览或登录。

密码与恢复码均遗失时，没有免验证重置入口。账户文件损坏、不可读或初始化后丢失时保持锁定，先检查文件权限或恢复此前保管的账户配置副本，再重新启动应用；此过程不应删除收藏库。

登录是应用访问保护，不是磁盘加密。原始数据库、图片、备份、导出长图和静态分享仍为普通文件；能直接读取文件或运行旧版本的人仍可能访问数据。敏感文件需结合操作系统账户、设备权限或磁盘加密保护；已经导出的分享不随退出登录撤销。

## 导入与档案更新

手动录入提供保存保护：同一次提交重试返回首次保存结果，同一草稿或队列项目只建立一份档案；新开空白录入仍可保存同款独立实物。提交前草稿同步失败时保留输入，待重试成功后再保存。

新增页在上传图片区下方提供 AI 识图录入，默认识别前两张卡牌图片，队列录入沿用队列图片。如需参考图，展开「另选识别图片」选择一至两张，收起即恢复默认来源。参考图仅用于识别，选图和应用 AI 结果均保留手写备注。保存卡牌需要至少一张上传图片或队列图片；缺图、必填项与输入格式问题在保存按钮旁提示并自动定位，可返回相应字段修正。服务端校验或提交前草稿同步失败同样显示明确提示，当前输入和选图保留；界面提示不替代服务端校验。

删除确认页打开后，档案、图片、财务或关联记录若发生变化，删除会被拒绝并返回详情页；请核对最新内容后重新打开删除确认页。核对与删除在同一事务内完成，拒绝删除时保留关联数据与媒体文件。

普通上传在保存前解码校验 JPG、PNG、WebP，最多 8000 万输入像素；损坏或截断文件被拒绝，合法文件保留原始字节。历史文件不自动重写。

编辑表单读取后，档案或图片若被其他操作更新，保存会报告冲突并保留当前输入及已选图片。请先核对最新资料，再重新打开编辑页继续处理。财务表单校验失败后，后续纠正不会被延迟回填覆盖。

1. 选择 UTF-8 CSV 或 XLSX 文件。XLSX 使用第一个工作表，公式须先转换为明确数值；每批最多 10 MB、10000 行、80 列。
2. 将文件表头映射到卡牌字段，忽略不需要的列。编号应在电子表格中保存为文本，以保留前导零。界面显示第一行样例。
3. 选择重复策略：默认跳过；更新只修改映射到的档案字段；“独立实物”明确新增另一张卡牌。卡牌 ID 优先匹配，其次证书号，再以主体、名称、运动、年份、平行版本和实物编号组合匹配。多重匹配必须提供 ID。
4. 建立预演，检查逐行字段、匹配 ID 和错误。预演不会创建或修改卡牌。新档案允许暂不带图片，后续由整理提醒补齐。
5. 执行后保留每行结果。每 50 行提交一个请求，每行独立事务；重复提交不会重复执行已完成的行。当前批次可继续执行或重试；“最近批次”列表已按界面要求移除，收起设置中的数据分类仍保留本页输入及批次状态。

「取得方式」列可填「买入」或「获赠」，留空按买入处理。获赠请填写取得日期（映射到购买日期）和正数数量，价格留空或填零。

新卡初始价格、日期、数量和估值写入正式财务流水；已有卡牌导入不覆盖财务历史或改变持仓状态。持仓状态与交易数量仍在详情页维护。

收藏页通过现有筛选和列表选择导出卡牌；已移除修改字段及其批量修改预演入口。档案修改可使用文件导入的更新策略，财务记录在卡牌详情页维护。

“撤销本批次”需要在界面确认：新增卡牌将删除，档案修改将恢复原值。系统对档案、流水、图片和分享引用检查操作后的指纹；已有后续修改时保留数据并报告冲突。可使用“重新建立预演”根据当前数据建立新批次。无效原始数据需要修正文件后再导入。

导入和导出面板只保留操作与结果，格式限制、数据范围和备份边界等说明统一放在设置页尾“帮助与版本”中的“使用说明”。

## 导出与换机

收藏页开启导出后，卡牌信息仍可打开详情；返回上一页会恢复原筛选、已加载卡牌、网格或列表视图、公开导出选项与勾选。选择只属于当前精确的筛选地址，不会转移到其他范围。

有勾选时，CSV/XLSX 仅导出已应用筛选范围内选中的卡牌，支持加载更多后继续勾选、选中已加载卡牌或选择全部匹配结果；无勾选时导出当前筛选全部结果。界面显示已选数量或当前范围。“仅导出公开档案”始终叠加过滤私密卡牌与字段。选中的卡牌已删除或被公开过滤排除时，不会扩大导出范围。

- CSV 导出当前筛选范围的档案字段，适合整理和外部核对。可能触发电子表格公式的文本会添加单引号前缀。
- 私密 XLSX 的 `Cards` 工作表保存档案，`Financial history` 单独保存原币交易、费用、估值和付款组成；完整财务流水用 `gift_in` 和 `gift_out` 区分获赠和赠送。财务页用于核对，不能作为档案字段回灌。
- “仅导出公开档案”只包含公开卡牌，排除私密备注和财务流水。
- 图片、草稿、分享配置、批次和全部历史的无损迁移仍使用设置中的完整备份与恢复。CSV/XLSX 不是数据库备份格式。

备份清单、恢复报告和孤立媒体恢复副本的规则统一见[数据备份说明](#backup)。

批次仅接受当前文件导入格式；已退役的档案修改/估值批次不再提供读取、执行、撤销或重新预演入口。

## 完整备份、恢复与存储

### 1. 数据保存位置

Card Vault 的收藏数据由以下内容共同组成：

- `dev.db`：卡牌、财务历史、录入草稿、模板、批量队列、分享集、报表设置、人工汇率修订、导入批次、心愿单、提醒状态及摘要周期。已有数据库可能含已停用功能的额外表，当前程序忽略其内容，不自动删表或清空。
- `uploads`：卡牌图片、已经完成预处理的队列 WebP，以及录入草稿图片。
- `studio-images`：保存已采用的展馆 PNG 和对应的手动卡面校准框，两者都包含在完整备份中。数据健康检查会解码当前成品，列出损坏或缺图的卡牌。与当前首图不匹配的历史 PNG 可在原处预览。[制图与补图](#studio-ai)
- `thumbnails`：首页和展墙使用的可重建 WebP 缩略图缓存，不属于必须备份的收藏原始数据。
- `entry-queue`：批量录入队列中尚待处理或可重试的源图片。
- `share-covers`：分享集自定义封面。
- `share-backgrounds`：分享集自定义背景。

心愿编辑草稿与寻卡窗口上下文保存在本机浏览器存储，不在上述数据库备份内；数据库中的录入草稿仍包含在备份中。心愿仅保存独立名称、主体、预算及备注，不提供关键词关系或多卡绑定。Git 同步源码不迁移个人收藏。

恢复和页面访问均不再执行旧寻卡、心愿、分析快照或回顾历史的自动清理。正常的心愿编辑、用户主动删除及数据健康工具保持原有行为。

普通录入草稿会一并保存选中的图片和旋转状态；重新打开草稿会恢复文件选择。完成录入或删除草稿后清理其临时图片。草稿图片受数据健康检查保护，不会被当作未引用图片清理。分享编辑草稿按当前收藏库隔离，保存在浏览器存储中，不随数据库备份迁移。

桌面端默认数据目录通常是：

```text
C:\Users\<你的用户名>\AppData\Roaming\Card Vault\data
```

如果在“设置 → 数据 → 维护”中修改过路径，请以设置页显示的路径为准。

### 2. 推荐备份方式

“设置 → 数据 → 备份与恢复 → 一键备份”会暂停本地数据服务，待进程退出后复制原始媒体并生成 SQLite 一致性快照，检查数据库完整性和媒体引用；缺失引用文件则清理本次不完整备份并报告失败，完成或失败后恢复服务。可由原图重建的 `thumbnails` 缓存不会进入备份。该方式无需退出程序，也是日常备份与换机前备份的首选。

每次点击「一键备份」都会在日期目录中创建独立的 data 子目录。应用检查可用空间并生成 `backup-manifest.json`，记录应用版本、各表行数、文件大小与 SHA-256。压缩归档时，请保留完整目录与清单。退出应用后直接复制的数据目录可用于原样保存，应用内恢复需要校验清单。

设置页显示本收藏库最近一次成功备份的时间、大小、图片文件数、创建时的校验结果和当前可用性。超过七天会提醒重新备份。没有成功记录的提示仅在桌面设置成功加载后显示。备份由用户发起，旧副本由用户管理。

### 3. 从备份恢复

1. 展开“设置 → 数据”，找到“备份与恢复”。
2. 点击“备份恢复”。
3. 选择一键备份生成的日期文件夹，或直接选择其中包含 `dev.db` 的 data 文件夹；日期文件夹中存在多次备份时，程序会使用最新的一份。
4. 确认恢复。程序在创建当前数据的安全副本和复制暂存数据前分别检查空间。
5. 来源及复制后的暂存副本均校验备份清单的文件数量、大小、SHA-256 与记录数，以及完整结构、索引、触发器、估值来源约束、状态记录、SQLite 完整性及关联完整性。通过后写入 `restore-report.json`（校验结果、结构版本、行数、安全备份位置），重建暂存清单，再执行目录切换。需要补齐图片顺序字段时，在暂存副本中完成；来源备份保持原样。
6. 恢复成功后本地数据服务会在应用内重新连接，当前页面自动刷新并加载备份数据；Electron 应用不会退出或重启。

暂存验证失败时不会替换当前数据；目录切换失败或切换后的最终布局/完整性检查失败会尝试恢复保留目录；最终检查成功后才清理临时原目录。临时原目录清理失败时保留其路径，不把成功恢复误报为失败。安全备份持续保留，发生服务重连失败时应依据提示和日志处理，不能将其视为完整恢复成功。

Windows 无法改名收藏根目录时，应用保留根目录，在其中逐项切换。若某个文件或子目录仍被占用，错误提示会指出具体项目。

目录切换前写入独立恢复操作记录，并刷新到磁盘。进程突然退出后，下次启动在创建数据目录之前检查该记录：最终校验尚未完成时恢复原目录，已完成时保留新目录；不会把恢复中缺失的目录初始化为空收藏。中断的暂存副本保留用于检查。模拟进程退出测试覆盖原目录移动后、新目录切换后和最终验证后三个边界；这不等同于物理断电测试。

### 4. 当前数据库基线边界

- 新建空数据库一次性创建完整结构。打开已有收藏时，先校验数据库完整性。旧格式的买卖流水表会在事务内扩展为支持获赠和赠送，保留原有记录、索引和触发器，零元买卖不会被重分类。若缺图片顺序字段，会自动添加该字段，已有图片沿用原来的首图与顺序。恢复备份时在暂存副本上完成此步骤。
- 管理设置只保留摘要周期；新库不再创建退役通知字段和卡牌人民币摘要字段，Prisma 不再读取或写入这些字段，财务记录由流水保存。已有库中的额外列不删改，也不解释为可用功能。
- 当前格式包括财务、管理、状态跟踪、财务索引队列和寻卡结构；仅有相同产品版本号不足以判定兼容。缺表、缺字段、缺索引/触发器或状态记录不完整时拒绝启动和恢复，原数据库保持不变。
- 备份必须带有有效的 `backup-manifest.json`；只接受完整的当前格式，早期不完整格式和无清单备份不支持。恢复报告使用 `restore-report.json`。
- 应用不会替换或转换历史卡牌原图。普通单卡上传继续保留原格式，批量录入队列的新图片仍按既定规则预处理为 WebP；首页会为首图另行生成最长边 640px 的 WebP 缩略图缓存。

### 5. 更换存储路径

- 更换路径会由独立存储进程把完整数据复制到暂存目录，`dev.db` 使用 SQLite 一致性快照，校验通过后才切换路径并重启应用。
- 新目标必须是空文件夹或可识别的 Card Vault 数据目录；程序不会覆盖无关的非空目录。
- 选择已有 Card Vault 数据的目录时，程序会先检查当前数据库格式与完整性；失败时保留原存储配置并恢复本地服务。
- 存储路径移动与数据库版本升级是两件事。移动路径不会改变卡牌内容或数据库结构。

### 6. 数据健康与清理

- “检查数据健康”会检查 SQLite 完整性、数据库引用但本地缺失的媒体，以及本地存在但未被引用的媒体。
- 卡图及队列成品仅接受 `/media/` 当前地址，不再转换 `/uploads/` 旧地址。路径格式无效时健康检查失败，清理被拒绝，不移动或删除文件。
- 健康检查本身只读取数据；未引用文件可在资源管理器中定位。
- “清理未引用文件”会二次确认并重新检查，暂停本地服务并复核数据库引用，将仍未被引用且位于受管媒体目录中的文件移至数据目录 `.recovery`，保留相对路径。没有自动清空或一键还原入口；需要找回时核对恢复副本，建议处理前先完整备份。
- `entry-queue` 源图、队列 WebP、分享封面和分享背景都在备份、恢复、健康检查及清理边界内。

### 7. 换机检查清单

- 在旧电脑设置页执行一次“一键备份”。
- 确认备份目录同时包含 `dev.db`、相关媒体目录和 `backup-manifest.json`。
- 在新电脑安装同一当前版本后，通过“备份恢复”导入。
- 恢复完成并自动刷新后，检查卡牌数量、图片、财务历史、草稿、模板、批量队列、分享背景、导入批次、心愿单和提醒状态。
- 确认无误前，不要删除旧电脑或外部存储上的最后一份完整备份。

存储路径和加密 AI 配置共用完整替换写入：临时文件写完并刷新后再替换原文件，写入或替换失败保留原配置。此机制不替代完整数据备份。

## 导出资源与规模边界

CSV/XLSX 先生成一致的 SQLite 临时快照，按每批最多 250 条读取卡牌及各类财务记录；CSV 按行写入，XLSX 按工作表写入 XML 后流式压缩，不在内存中构造整本工作簿。文件完整生成后开始下载，每块 64 KiB，并限制下载队列。大文件需要等待生成，且临时磁盘需要容纳数据库快照、工作表及最终文件。正常完成、取消和异常会关闭句柄并清理该任务目录；强制结束进程的残留文件仍由系统临时目录管理。

每个服务进程最多同时进行两个导出，卡牌导出共用此额度及快照、超时、下载取消和清理流程；生成最长 10 分钟，数据库快照最长 30 秒。XLSX 每表最多 1,048,576 行（含表头），超出后建立带序号的工作表并重复表头。选中导出最多 10000 张，无勾选的搜索结果导出没有此选择上限；导入仍限制为 10 MB、10000 行、80 列，只读取第一张表。公开过滤、CSV 文本转义和财务口径沿用原规则。简化寻卡不再提供独立关键词或心愿 CSV 清单导出；卡牌 CSV/XLSX 导入导出及完整备份格式保留。

性能基准命令见[开发维护](./development.md#checks)。旧规模测试的机器条件、观测数值与限制已移至[历史基准](./history/development.md#data-benchmarks)，不作为当前版本的性能承诺。

## AI 网络与代理

入口为“设置 → AI → 网络与代理”，直接选择连接方式，点击该区的“保存设置”。代理同时用于读取模型、连接测试、识图、制图、文案和组合分析。

### 从零理解连接方案

一次 AI 请求的路径是：本项目 → AI 服务地址。代理是在途中转发请求的服务，使用代理后路径变为：本项目 → 代理 → AI 服务地址。

- **模型**：处理内容的能力名称。同一个模型可能由官方接口、其他服务商或本机服务提供。
- **Endpoint**：实际接收请求的 AI 服务地址。网络是否需要代理，取决于这个地址和当前网络，因此分流按地址判断。
- **代理服务器地址与端口**：转发服务的入口，来自代理软件或服务商，与 AI 的 Endpoint 分别设置。
- **系统代理与规则模式**：代理软件可以向系统提供入口，再按访问的域名决定直连或转发。PAC 是系统按地址选择连接方式的一种规则。

#### 适合日常使用的方案

1. 在已有代理软件中开启系统代理，并使用适合当前网络的规则模式。
2. 本项目选择“自动”，保存设置。通常无需在项目中填写代理地址、端口和认证。
3. 项目将 AI 接口地址交给系统规则解析：规则指向代理则转发，规则为直连则直接访问。模型名称不参与这个判断。

有些代理软件让请求先统一进入本机代理，再由软件内部规则决定最终直连还是转发；使用 PAC 时，系统也可以直接给项目返回“直连”或“走代理”。两种情况都可以按服务地址分流，无需逐个模型填写代理。

这种方式让不同 AI 服务按地址分流，也能跟随代理软件更换端口。规则由代理软件或系统提供；单纯安装或打开软件，不一定已经启用系统代理。若当前电脑另有环境变量指定代理，项目会优先采用它们；普通用户通常无需额外设置这些变量。

当前“自动”使用已有配置和规则，不主动探测每个服务的网络可达性。电脑没有提供代理信息时会直连；项目无法凭模型名称推断代理软件端口、账号或该网络下的可达性。接口返回认证、额度或模型权限错误时，也不能据此认定需要代理。

代理软件无法提供系统代理，或使用远程代理网关时，再选择“手动代理”。所有服务均可直接访问时，可以选择“直连”。换设备后先用“自动”，由新设备提供适用的网络规则。

界面只保留配置项、密码保留提示及地址分隔提示；详细说明集中在本页。

| 方式 | 行为与适用环境 |
| --- | --- |
| 自动（默认） | 优先使用当前进程的 HTTP_PROXY、HTTPS_PROXY、ALL_PROXY 和 NO_PROXY；桌面端没有对应环境代理时，按目标地址读取系统代理及 PAC 规则。适合经常更换网络或设备。 |
| 手动代理 | 自行选择 HTTP、HTTPS 或 SOCKS5，填写代理服务器主机名/IP、实际端口和可选用户名、密码。既可使用本机代理软件，也可使用远程网关。 |
| 直连 | AI 请求不使用代理，适合目标服务可直接访问的网络。 |

### 手动设置

1. 从代理软件或代理服务商处取得协议、服务器地址和端口；本项目不预设某个软件、固定端口或本机地址。
2. 协议选择代理服务器本身的协议。代理服务器是 HTTP 时，即使 AI 接口为 HTTPS，也应选择 HTTP。
3. 地址只填写主机名或 IP，协议、端口和认证信息分别填写。支持可选代理用户名及密码，代理密码加密保存，已保存时留空表示保留，也可显式清除。
4. “不经过代理的地址”以逗号分隔，支持精确域名/IP、.example.com、*.example.com、主机:端口、IPv4/IPv6 CIDR 网段（如 192.168.0.0/16、fd00::/8）和 *。网段只匹配地址中直接填写的 IP，不额外解析域名。本地服务默认绕过代理；也可将可直连的 AI 服务加入此列表。
5. 点击“保存设置”。同页的“读取模型”和“测试连接”会使用当前代理草稿，只有主动点击才发起请求。

“测试连接”的结果会简短显示本次线路来自系统规则、环境变量、手动配置或直连/绕过规则，以及实际使用的代理协议；不显示代理地址、用户名或密码。成功仅确认文本请求，不代表所选模型支持识图。代理认证、地址解析、连接拒绝及安全证书问题使用不同提示。更改配置或离开页面会取消当前请求，取消会向上游连接传递；不保证服务商一定停止计费。

OpenAI 的 Endpoint 仍为 https://api.openai.com/v1/chat/completions，不要将其替换为代理软件的本机地址。代理决定连接路径，Endpoint 决定 AI 服务地址。

### 自动模式与开发环境

环境变量支持小写形式，优先级为小写高于同名大写、目标协议的代理高于 ALL_PROXY。HTTPS 请求读取 HTTPS_PROXY，HTTP 请求读取 HTTP_PROXY。支持 http://、https://、socks5:// 与 socks5h:// 形式；地址及端口取当前环境的真实配置。NO_PROXY 规则会绕过代理。

桌面端在没有对应环境代理时通过 Electron 读取系统代理及 PAC 结果，按每次请求的目标地址解析。独立 Node/Web 开发进程无法读取 Electron 系统会话，自动模式没有环境代理时直连；也可通过 CARD_VAULT_AI_PROXY_JSON 配置与界面相同的 mode、protocol、host、port、username、password、noProxy 字段。环境中的凭据由使用者管理，不要提交进源码。

代理连接失败不会自动尝试直连。设置为自动时，只有环境绕过规则、系统明确的 DIRECT 规则，或未配置代理，才会直连。不会修改全局系统代理或其他网络应用。

系统规则目前支持 HTTP、HTTPS、SOCKS5 和 DIRECT。Chromium 的 PAC 格式中，`SOCKS` 与 `SOCKS4` 表示 SOCKS4，不会被误当作 SOCKS5；遇到这些规则时会提示改用受支持的手动配置。详见 [Chromium 代理协议说明](https://chromium.googlesource.com/chromium/src/+/HEAD/net/docs/proxy.md)。多个代理候选按系统提供的顺序使用；仅遇到明确的连接建立或代理握手失败时尝试下一候选，系统明确列出的 DIRECT 才允许直连。TLS 验证失败、连接中断或 AI 接口返回的认证/额度错误不触发候选切换。

接口重定向后会按新地址重新计算线路与绕过规则。跨服务地址跳转会去除原请求的认证及其他私有 Header；不跟随 HTTPS 降级到 HTTP 的地址，不接受带用户名/密码的重定向，最多跟随 10 次。服务依赖跨域认证时应直接填写最终 Endpoint。

### 设备与凭据

代理设置保存在当前设备的 AI 用户配置中，不写入收藏数据库，也不随收藏备份、CSV/XLSX 或分享包迁移。换设备后建议先使用自动模式，或填写新设备适用的代理信息；手动复制加密配置可能需要重新输入密码。登录凭据不用于日志，模型接口错误中的 API Key 会被遮蔽。

已保存凭据暂时无法解密时，保存其他设置仍保留原密文，并继续显示恢复提示。仅明确提交新凭据或清除操作才替换对应密文；加密不可用时不能保存新密码。此规则同时适用于内置服务、自定义服务、旧 Azure 配置迁移及代理密码。

验证使用本机模拟服务，覆盖代理协议、隧道连接、认证、TLS、环境变量、绕过规则、候选切换、重定向和取消；HTTPS 仅在独立测试子进程中信任测试证书，不关闭生产证书校验。真实 Electron PAC 测试使用隔离会话，不修改 Windows 系统代理。模型列表和连接测试还须覆盖取消后关闭上游连接、中英文提示及窄窗口。执行方法见[开发维护](./development.md#checks)，结果见[当前版本](./README.md#current-release)；本机测试不能替代其他设备、代理软件及分发文件的实际验收。

## AI 制图与合影

在「设置 → AI」中，识别与分析、制图与合影、网络与代理各自保存。每区的操作按钮靠左排列，「保存设置」排在最后。保存后可在本区查看结果，其他区尚未保存的编辑会保留。

「制图与合影」使用 OpenAI 图片编辑接口，默认模型为 `gpt-image-2`。原有配置沿用 OpenAI 密钥，也可在此区保存独立密钥。密钥在本机加密保存，生图沿用已保存的代理设置。切换识别服务不会改变图片模型或密钥来源。「检查已保存模型」只查询模型信息。要验证实际生图效果，可在单卡编辑页生成展馆图。首次生成成功后直接使用，重新生成的图片在点击「采用新图」后替换成品。

单卡生成和重做都使用当前首图。提示词描述卡面、装裱和摄影要求，不写人物姓名。摄影样图只提供窗光、墙面、台面和透明亚克力卡架的局部参考。已评级卡按首图保留原壳及标签上的机构、分数和证书号；无评级卡使用标准透明磁吸卡砖。常规卡使用透明卡架，特大卡直接置于台面。

在单卡编辑页的「AI 展馆图」中，点击「上传展馆图」可从本机选取 JPG、PNG 或 WebP（最多 15 MB）。即使没有配置生图密钥或上次生成失败，也可以上传。预览后点击「采用新图」，展示和合影就会使用这张展馆图；已有成品时，点击当前成品下方的「保留原图」会丢弃预览；首次补图时可点击「放弃新图」取消。上传走本地处理流程，卡牌录入首图保持原样。

单卡生图被拦截时可查看请求 ID。如果 OpenAI 同时返回审核阶段或类别，可展开「审核详情」查看。旧的失败记录仅显示当时保存的信息。

有卡牌待生成时，「待生成」数量旁会出现「补生成展馆图」。合影的「AI 展台精修」使用同一图片模型、密钥和代理。构图与校准操作见[导出合影](./collection-guide.md#group-photo)。
