# Card Vault 数据备份说明

适用产品版本：`1.3.1`；数据库结构标记：`1.3.0`，须通过完整当前格式校验。

## 1. 数据保存位置

Card Vault 的收藏数据由以下内容共同组成：

- `dev.db`：卡片、财务历史、录入草稿、模板、批量队列、分享集、收藏视图和时间点快照、报表设置、人工汇率修订、导入批次、心愿单、提醒状态及摘要周期。
- `uploads`：卡片图片与已经完成预处理的队列 WebP。
- `thumbnails`：首页使用的可重建 WebP 缩略图缓存，不属于必须备份的收藏原始数据。
- `entry-queue`：批量录入队列中尚待处理或可重试的源图片。
- `share-covers`：分享集自定义封面。
- `share-backgrounds`：分享集自定义背景。

桌面端默认数据目录通常是：

```text
C:\Users\<你的用户名>\AppData\Roaming\Card Vault\data
```

如果在“设置 → 数据 → 存储”中修改过路径，请以设置页显示的路径为准。

## 2. 推荐备份方式

“设置 → 数据 → 备份与恢复 → 一键备份”会暂停本地数据服务，待进程退出后复制原始媒体并生成 SQLite 一致性快照，检查数据库完整性和媒体引用；缺失引用文件则清理本次不完整备份并报告失败，完成或失败后恢复服务。可由原图重建的 `thumbnails` 缓存不会进入备份。该方式无需退出程序，也是日常备份与换机前备份的首选。

如需压缩归档，请压缩一键备份生成的完整目录，保留校验清单。退出程序后直接复制的数据目录可用于原样保存，但不带清单的副本不接受应用内备份恢复；不要只复制数据库或只复制图片。

一键备份会按日期创建目录；同一天多次备份会生成独立 data 子目录，不覆盖已有备份。

新备份写入 `backup-manifest.json`，包含应用版本、全部数据表数量、文件大小及 SHA-256。恢复前核对完整文件清单与表数量；不接受缺失或不一致的清单。无清单或非当前数据库格式的备份直接拒绝，不转换、不补表。恢复在暂存区写入 `restore-report.json`，记录校验结果、恢复后数量和安全备份位置。

## 3. 从备份恢复

1. 展开“设置 → 数据”，找到“备份与恢复”。
2. 点击“备份恢复”。
3. 选择一键备份生成的日期文件夹，或直接选择其中包含 `dev.db` 的 data 文件夹；日期文件夹中存在多次备份时，程序会使用最新的一份。
4. 确认恢复。程序会先备份当前数据，再将来源复制到暂存目录。
5. 来源和暂存副本都只读校验当前完整结构、索引、触发器、状态记录、SQLite 完整性及关联完整性；全部通过后才替换当前目录，不执行升级、费用归属回填或零金额转换。
6. 恢复成功后本地数据服务会在应用内重新连接，当前页面自动刷新并加载备份数据；Electron 应用不会退出或重启。

暂存验证失败时不会替换当前数据；目录切换失败或切换后的最终布局/完整性检查失败会尝试恢复保留目录；最终检查成功后才清理临时原目录。临时原目录清理失败时保留其路径，不把成功恢复误报为失败。安全备份持续保留，发生服务重连失败时应依据提示和日志处理，不能将其视为完整恢复成功。

## 4. 当前数据库基线边界

- 新建空数据库一次性创建完整的当前结构。已有数据库只校验，不执行 ALTER TABLE、补表、回填、旧版结构识别或升级前快照。
- 当前格式包括财务、管理、状态跟踪及财务索引队列等完整结构；仅有相同产品版本号不足以判定兼容。缺表、缺字段、缺索引/触发器或状态记录不完整时拒绝启动和恢复，原数据库保持不变。
- 备份必须带有有效的 `backup-manifest.json`；旧格式数据与无清单备份不再支持。恢复报告使用 `restore-report.json`。
- 应用不会替换或转换历史卡片原图。普通单卡上传继续保留原格式，批量录入队列的新图片仍按既定规则预处理为 WebP；首页会为首图另行生成最长边 640px 的 WebP 缩略图缓存。

## 5. 更换存储路径

- 更换路径会由独立存储进程把完整数据复制到暂存目录，`dev.db` 使用 SQLite 一致性快照，校验通过后才切换路径并重启应用。
- 新目标必须是空文件夹或可识别的 Card Vault 数据目录；程序不会覆盖无关的非空目录。
- 选择已有 Card Vault 数据的目录时，程序会先检查当前数据库格式与完整性；失败时保留原存储配置并恢复本地服务。
- 存储路径移动与数据库版本升级是两件事。移动路径不会改变卡片内容或数据库结构。

## 6. 数据健康与清理

- “检查数据健康”会检查 SQLite 完整性、数据库引用但本地缺失的媒体，以及本地存在但未被引用的媒体。
- 健康检查本身只读取数据；未引用文件可在资源管理器中定位。
- “清理未引用文件”会二次确认并重新检查，暂停本地服务并复核数据库引用，将仍未被引用且位于受管媒体目录中的文件移至数据目录 `.recovery`，保留相对路径。没有自动清空或一键还原入口；需要找回时核对恢复副本，建议处理前先完整备份。
- `entry-queue` 源图、队列 WebP、分享封面和分享背景都在备份、恢复、健康检查及清理边界内。

## 7. 换机检查清单

- 在旧电脑设置页执行一次“一键备份”。
- 确认备份目录同时包含 `dev.db`、相关媒体目录和 `backup-manifest.json`。
- 在新电脑安装同一当前版本后，通过“备份恢复”导入。
- 恢复完成并自动刷新后，检查卡片数量、图片、财务历史、草稿、模板、批量队列、分享背景、收藏视图、时间点快照、导入批次、心愿单和提醒状态。
- 确认无误前，不要删除旧电脑或外部存储上的最后一份完整备份。
