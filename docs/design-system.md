# 版式与字体规范

同类功能使用相同的字号、字重、尺寸和交互状态；颜色随应用主题变化。此规范覆盖收藏、卡片录入与档案、统计、回顾、展示、分享编辑、目标与寻卡、设置、数据管理及帮助页面。

## 文字层级

公共变量集中在 `app/styles/design-tokens.css`，在其他样式之前载入。页面和 CSS Module 引用同一组变量，避免局部重复定义相近字号。

| 用途 | 字号 | 字重 |
| --- | --- | --- |
| 页面主标题 | 28–36px，随窗口变化 | 700 |
| 弹窗标题 | 24px | 600 |
| 模块标题 | 18px | 600 |
| 卡片／子模块标题 | 16px | 600 |
| 正文、普通输入与常规按钮 | 14px | 正文／输入 400，按钮 500 |
| 字段标签、紧凑按钮和表格内容 | 13px | 标签／按钮 500，表格正文 400 |
| 注释、辅助信息、图表刻度 | 12px | 400，必要的状态强调使用 500 |

普通界面统一使用 Arial、Microsoft YaHei 及系统无衬线回退；代码、路径中的代码片段和键位采用 Consolas 等等宽字体。字重只使用 400、500、600、700。正文行高 1.6，按钮和输入行高 1.4，标题行高 1.3。

同为数字也需按用途区分：摘要指标采用 20–28px，回顾的突出数量采用 36px，表格和辅助计数按正文或辅助字号显示。不能把带有 `.h1` 类的数量误当作页面标题。金额和需要列对齐的数字沿用等宽数字排版。

## 功能控件

- 常规按钮与输入以 40px 为基准，紧凑按钮／筛选区以 36px 为基准；纯图标工具以 32px 为基准。触屏目标保留至少 44px 的专属规则。
- 普通按钮、业务输入使用 8px 圆角，主内容面板使用 12px 圆角。多行文字、长英文按钮允许自然增高，不通过固定高度裁切文字。
- 默认按钮和次要按钮共用中性配色及悬停状态。主要操作沿用主题强调色，危险操作保留危险色；层级通过用途确定，不能在不同页面任意改变按钮字重。
- 经典主题的主按钮使用较深橙色，让 14px 白字达到至少 4.5:1 对比度；其他主题使用各自通过检查的强调色，不更改主题色调。
- `.btn` 的字体、间距与状态由公共控件规则提供。局部样式仅保留必要的紧凑布局、换行和宽度约束，不另建一套按钮文字规则。
- 同类表单的标签和输入分别使用 13px、14px，复选框与单选框统一 18px。滑杆、文件选择器和颜色选择器按其原生用途布局，不套用普通文本框尺寸。
- 同功能的网格／列表切换使用同样的图标尺寸；组合分析关闭键使用现有 SVG 图标，不再依赖文本乘号和单独的字体。
- 文件选择按钮也使用统一的字体和内层样式，避免录入、数据导入与设置分别显示不同的原生按钮。

## 展示内容的边界

展馆和展示单卡的作品标题采用统一的 Georgia、Times New Roman、SimSun 衬线回退，保留较大的作品标题层级。展馆面板可沿用细线字段、主题配色、色样和展签式标题；功能输入、选项及按钮则使用公共界面字体和 14px／40px 标准，避免恢复到任意数值。

分享集成品、公开预览和静态导出的现代／编辑／典藏排版属于用户选择的作品设计，不套用后台表单样式。回顾 PNG 和原始卡片图片同样不因管理界面字体整理而改变。应用主题只更换颜色与背景，不为同一个功能另设字号。

## 检查方法

`tests/ui/design-consistency.spec.mjs` 在中英文主要页面检查按钮、输入、标题、字体及溢出，并在四种应用主题中核对标题层级；图标切换比较真实计算样式。原有界面与截图回归继续覆盖表单、数据、分享和展馆交互。

新增样式优先引用上述变量。确实需要展示作品或指标的独立层级时，先明确用途，再复用或扩展公共变量；不要按当前页面观感随意增加 0.78rem、0.85rem、650、850 等近似值。

## 应用主题与扩展

设置 → 主题提供“经典、极简展厅、午夜典藏、暖纸档案”。主题区只展示预览图与名称，用户选择后立即生效并保留；各主题平等呈现，不设置默认标记或恢复入口。经典主题的各页面统一使用首页背景图。

主题覆盖首页、展示、卡片档案与财务、组合分析、分享编辑、寻卡和设置。首页保留完整背景，展示页降低背景权重以衬托完整卡图，数据和编辑页面优先保证内容可读。分享集的主题、背景、预览和静态导出独立于应用主题。

### 保存与首屏

- `card_vault_app_theme` 保存为一年有效期的本地 Cookie，仅包含主题 ID，不写入收藏数据库。浏览器或桌面配置被清除后回到经典。
- 根布局在服务端读取 Cookie，将已校验的主题标识和颜色变量直接输出到 HTML，避免等待客户端加载后才改变颜色。
- 未知、失效或异常主题值回退到经典。主题 ID 必须来自固定注册表，不允许从 Cookie 注入颜色、CSS 或外部背景地址。
- 背景以本地 WebP 随应用发布，不需要联网。新增三张背景由 imagegen 生成，原始尺寸 1672 × 941，压缩后合计约 326 KiB；资源位于 `public/app-themes/`。

### 添加主题

1. 在 `public/app-themes/` 添加经过压缩的本地背景。
2. 在 `lib/app-themes.ts` 的 `appThemes` 注册表增加唯一 ID、中英文名称、背景路径及完整颜色配置。设置卡片与允许的主题 ID 随注册表自动扩展。
3. 新的组件沿用 `--ink`、`--surface`、`--surface-soft`、`--accent`、`--muted-ink` 等公共变量。迁移已有组件时使用 `--theme-*` 变量并保留原色值作为 fallback，避免影响经典主题。预览缩略图若需专属颜色，可在 `app/themes.css` 添加对应样式。
4. 不修改 `lib/share-themes.ts` 或导出渲染样式，它们属于分享集主题系统。
5. 运行主题单元测试和 `tests/ui/themes.spec.mjs`，检查颜色对比、键盘选择、重载与无 JavaScript 首屏、手动切换、各主要页面及分享预览独立性；检查截图后再更新基线。

### 验证范围

自动检查正文、辅助文字、链接、按钮及财务正负状态的主要颜色组合达到 4.5:1 对比度。真实页面仍需检查半透明面板、图片边缘、图表与交互状态，不能仅凭颜色变量测试判定全部视觉合格。

全局样式入口 `app/globals.css` 先引入 `app/styles/design-tokens.css`，再载入基础、控件及各功能样式，应用主题随后覆盖颜色。展示专属规则集中在 `showcase.css`，寻卡规则集中在 `scout.css`，展馆布局及调色板分别位于 `immersive.css` 和 `immersive-scenes.css`。组件专属样式继续使用 CSS Module，字号和尺寸引用同一套公共变量。
